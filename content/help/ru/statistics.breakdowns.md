Разрез задаёт, по чему группировать строки. Их четыре: **пользователь**,
**проект**, **тип файла**, **машина**. В кабинете доступны только проект и тип
файла ([Что попадает в кабинет](/help/statistics.personal.scope)).

Каждый разрез собирается из трёх источников сразу, и вот тут начинаются
тонкости: под одной строкой таблицы могут стоять числа, посчитанные по-разному.

## Пользователь считается по-разному в трёх источниках

| источник | кого считает пользователем |
|---|---|
| файлы | заливщика, с откатом на владельца проекта |
| задачи | заливщика исходного файла |
| архив обработок | владельца проекта — атрибуции по файлу там нет |
| лента транзакций | плательщика, то есть того же владельца |

Практическое следствие: в одной строке колонка «Файлы» может отвечать «что залил
этот человек», а «Обработки» и «Спенд» — «что происходило в проектах, которыми он
владеет». Для владельца-одиночки это одно и то же, для расшаренного проекта —
нет.

Если нужен точный ответ «кто сколько наработал в чужом проекте», разрез по
пользователю его не даёт и дать не может, пока у обработки нет ссылки на задачу.

## Машина — это имя, а не идентичность

Машина приходит из двух мест: в задачах это запись из реестра компьютеров, в
архиве — суффикс имени файла журнала. **Сквозного идентификатора у машины нет.**

Поэтому разрез сливает их только при совпадении имён, а при расхождении вы
увидите две строки про одну и ту же машину. Это осознанный выбор: две видимые
строки лучше тихой суммы, в которой не разобраться.

Ещё одно: **у файла машины нет** — файл не знает, кто его потом обработает.
Поэтому в разрезе по машинам метрики «Файлы» и «Объём» пустые, и под осями об
этом написано отдельной строкой.

## История удалённого проекта не сливается в одну строку

При удалении проекта ссылка в архиве обнуляется, но записи остаются. Такие строки
группируются по имени проекта из самого архива, а не по пустому ключу: иначе все
удалённые проекты слиплись бы в одну строку под именем первого из них.

Провалиться в такую строку нельзя — проекта уже нет. Видно её, тем не менее,
вместе со всеми: это состоявшаяся работа и состоявшиеся деньги.

## Тип файла: тоже два источника

У файлов тип берётся из расширения имени, у обработок — из поля исходного типа в
журнале машины. Совпадают они обычно, но не по построению: строка «mov» в
колонке файлов и та же строка в колонке обработок посчитаны независимо.

Строка «без расширения» — это реальная группа, а не ошибка: файлы без точки в
имени существуют.

## Спенд в разрезах по типу и по машине

Лента транзакций не знает ни типа файла, ни машины — она знает плательщика,
проект и задачу. Тип и машину к списанию подтягивает архив обработок, по ссылке
на ту же единицу работы.

Отсюда следствие: **пока архив не импортирован, спенд в этих двух разрезах
собирается в строку с пустым ключом**. В разрезах по пользователю и по проекту
он виден всегда — там ключ есть в самой транзакции.

## Ограничение выборки

Не больше 200 строк, отобранных объединением топов по каждой метрике. Сколько
отброшено — написано под таблицей.
