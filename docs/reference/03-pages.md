# 03 — Страницы и экраны

Всё, что рендерится в браузере. Роуты — из `app/`, компоненты — из
`components/`.

## Публичная зона

| Путь | Файл | Что показывает |
| --- | --- | --- |
| `/` | `app/page.tsx` | Главная = каталог. Хедер, `AboutShowreel` (промо-видео из `public/promo_video.mp4`), затем бесконечная лента работ. Первая страница берётся из `unstable_cache` (тег `published-videos`, `revalidate: 60`) — без этого TTFB упирался в round-trip к удалённой базе. | `/about` | `app/about/page.tsx` | Шоурил + текст (заглушка `TODO(Vanya)`) + блок контактов, который появляется только если заданы `NEXT_PUBLIC_CONTACT_EMAIL` / `NEXT_PUBLIC_CONTACT_TELEGRAM`. |

| `/suggest` | `app/suggest/page.tsx` | Форма «предложить функцию» с вложениями. Вложения реально уезжают в R2 (`/api/feature-suggestions/upload`), а сама заявка отдаёт **503** — доставка не подключена. |

### Рабочая область: устройство

Провайдер `components/account/workspace/workspace-context.tsx` (~1500 строк) —
единственный держатель состояния: список проектов, дерево файлов, выделение,
буфер обмена, чат, диалоги, опрос `delta`.

```
WorkspacePageClient
└── WorkspaceProvider                    ← всё состояние
    └── WorkspaceLayout
        ├── ToolsWorkspace               ← если ?tab=tools
        ├── ProjectsColumn               ← только полный режим
        ├── WorkspaceTopbar
        ├── FullMode | SimpleProject | AllProjectsPage
        ├── MobileWorkspace              ← < lg
        └── ClipboardPanel · ContextMenu · MoveDialog
            · PreviewDialog · ShareDialog · WorkspaceDialogs
```

**Разделы списка проектов** (`?tab=`, пункты бокового меню):

| `tab` | Что | Заметка |
| --- | --- | --- |
| `projects` | свои проекты | по умолчанию |
| `shared` | расшаренные мне | роль показывается на карточке |
| `tools` | инструменты | своё дерево компонентов внутри того же провайдера |
| `archive` | архив | обработки по этим проектам не идут |
| `trash` | корзина | 🔧 в кабинете помечена как «не подключено» (`trashNotWired`) |

**Режимы** (`density`, хранится в `localStorage` под `ffworks-ws-density`):
- `full` — три колонки: проекты, дерево, нижняя панель;
- `simple` — две панели IN / OUT для одного проекта.

**Виды дерева** (`view`, `localStorage` `ffworks-ws-view`): `list`, `grid`,
`columns`.

**Нижняя панель** (`BottomTab`): `preview` (выбранный файл), `desc` (описание
проекта), `settings` (параметры обработки + пауза), `chat`.

**Опросы:** дерево — `delta` каждые 4 с; чат — каждые 6 с.

### Что можно сделать в рабочей области

Загрузить файл (напрямую в R2 с прогрессом), создать папку, переименовать,
переместить (диалог или drag), скопировать/вырезать/вставить через буфер,
удалить (в корзину), скачать, открыть превью с перелистыванием стрелками,
выделить несколько (Cmd/Ctrl-клик, Shift-диапазон), расшарить проект,
поставить на паузу, отправить в архив, править параметры обработки, читать
описание, писать в чат.

Все кнопки гейтятся `projectCapabilities()` — пересечением прав зоны и роли в
проекте (см. [06](./06-auth-and-access.md#5-права-на-проект)).

## Админка (`/admin`)

Тройная защита: `proxy.ts` (JWT + `isElevated` + `Cache-Control: no-store`),
`app/admin/layout.tsx` (сверка с базой) и `requireCapabilityPage` на каждой
странице раздела — тег решает, существует ли раздел для этого человека
(см. [06](./06-auth-and-access.md)). Внутри — тот же `WorkspaceShell`, плюс
`AdminShell`.

### Реестр инструментов, а не дерево меню

Разделы админки описаны одним реестром —
[`components/admin/shell/nav-config.ts`](../../components/admin/shell/nav-config.ts).
В нём два независимых понятия, и путать их нельзя:

| Поле | На какой вопрос отвечает |
| --- | --- |
| `areas` | **где** инструмент лежит и откуда до него добраться. Их может быть несколько |
| `capability` | **кому** он доступен. Ровно один тег, включает суперадмин |

Слей их — и перенос инструмента в другой раздел молча менял бы, кто имеет к нему
доступ. Разные вопросы, разные поля.

Области — строки бокового меню; `areas[0]` считается основной: она стоит в
крошках и подсвечивается. «Люди» лежат сразу в двух (`access`, `insights`):
заводят и блокируют людей — это доступ, смотрят, кто вообще есть, — это
аналитика рядом с посетителями. Искать будут в обоих местах, и в обоих найдут.
«Удалённый доступ» — в `access` и `pipeline` по той же логике: в конвейере
машинами пользуются, а заводят их там, где выдают доступ.

| Область | Хаб | Инструменты |
| --- | --- | --- |
| Главная | `/admin` | Обзор (`/admin/overview`), Контент |
| Аналитика | `/admin/insights` | Люди, Посетители, Статистика |
| Тарифы | `/admin/billing` | биллинг |
| Доступ | `/admin/access` | Люди, Права доступа, Удалённый доступ, Журнал |
| Конвейер | `/admin/pipeline` | сам конвейер; строка меню отдельная, не в свёртке |

Область видна, пока в ней остаётся хоть один доступный инструмент.

### Раскладка повторяет кабинет

Свёртки «Админка» нет: разделы админки лежат в боковом меню так же плоско, как
разделы кабинета выше. Свёртка добавляла клик перед каждым переходом и прятала
половину админки от глаз.

| Слой | Что показывает |
| --- | --- |
| Боковое меню | области, плоским списком под подписью «Админка». Конвейер первым — открывают его чаще всего остального вместе |
| Колонка инструментов | инструменты текущей области, как колонка проектов в кабинете: ширина тянется и запоминается |
| Шапка | крошки со ссылками наверх, переключатель «Полный / Упрощённый», выход на сайт |
| Хаб области | карточки с описаниями — главная страница области |

Крошки кликабельны, и это не украшение: в упрощённом виде колонки нет, и стрелка
с названием области — единственный путь на главную страницу раздела. Стрелка
ведёт на ближайший уровень (со страницы внутри раздела — в сам раздел), название
области — всегда в хаб; так доступны оба уровня.

Переключатель прячет и показывает колонку — тот же смысл, что у полного и
упрощённого вида в кабинете. Ключ хранения свой (`ffworks-admin-density`): свернув
колонку в админке, человек не ждёт, что схлопнется список проектов в кабинете.

Шапка админки отличается от кабинетной подсвеченной иконкой области и тонкой
линией акцента сверху — чтобы по одному взгляду было видно, что это админская
зона. Раскладка при этом та же: переучиваться при переходе не приходится.

### Главная страница области — список, а не первый инструмент

Нажав на область, человек должен попасть на страницу со всеми её инструментами.
В упрощённом виде, где колонки нет, это единственный способ узнать, что в области
вообще есть. Поэтому дашборд студии переехал с `/admin` на `/admin/overview` и
стал обычным инструментом, а `/admin` — хабом «Главной».

Исключение — область, у которой ровно один свой инструмент: список из одной
карточки хуже прямой ссылки. Так живёт конвейер (`isAreaHub: true`). Инструменты,
у которых конвейер вторая область — «Удалённый доступ», «Без цены», — открываются
из своих основных областей и из колонки.

### `npm run admin:check`

Инструмент, до которого нельзя добраться, — плохой инструмент. Чтобы это не
осталось благим пожеланием, есть проверка
[`scripts/admin-nav-check.mjs`](../../scripts/admin-nav-check.mjs). Она падает,
если:

- у страницы `app/admin/**/page.tsx` нет записи в реестре — раздел появился, а
  входа в него нет;
- у записи нет области или область не объявлена;
- `href` записи ведёт на несуществующую страницу;
- в области не осталось ни одного инструмента;
- href области ведёт на инструмент, хотя своих инструментов у неё больше одного —
  то есть её главная страница показывает первый раздел вместо списка.

Вложенные страницы зарегистрированного раздела (`/admin/remote-access/api`)
пропускаются: до них добираются изнутри родителя, и проверка ручается за верхний
уровень.

### Четыре группы, а не плоский список

Меню показывает **только группы**; инструменты открываются карточками со
страницы-хаба. Плоский список из восьми пунктов перестал читаться, а расти ему
ещё есть куда: теперь при новом разделе растёт хаб, где место есть, а не меню.

| Группа | Хаб | Инструменты |
| --- | --- | --- |
| Главная | `/admin` (сам обзор) | Обзор, Контент |
| Аналитика | `/admin/insights` | Посетители, Статистика |
| Тарифы | `/admin/billing` | биллинг (пока один — строка меню ведёт прямо в него) |
| Доступ | `/admin/access` | Люди, Права доступа, Удалённый доступ, Журнал |

Группа видна, пока в ней остаётся хоть один доступный инструмент. У «Главной»
хаба нет — им служит сам обзор, поэтому карточки группы выводятся на нём
(`AdminHubCards` с `exclude="/admin"`); без этого «Контент» стал бы недостижим.

| Путь | Что показывает |
| --- | --- |

| `/admin/billing` | Тарифы, баланс, начисления. |

| `/admin/remote-access` | Токены доступа и парк машин под ними: статус, последний пульс, текущая задача; создание, ротация и отзыв `rc_`, отзыв `mch_` (ротации у него нет — значение показывалось один раз). |

| **`/admin/pipeline`** | **Конвейер.** Три колонки: пользователи → проекты → дерево. Плюс нижняя полоса состояния, окно очереди задач и диалог настроек (обход IN, общие словари). |

Меню — `components/admin/shell/nav-config.ts`. «Конвейер» поднят на один уровень
со свёрткой «Админка»: это рабочий инструмент, до него не должно быть двух
кликов. На узком экране группы не сворачиваются — подпись группы и её
инструменты идут подряд.

### Конвейер использует ту же рабочую область

Колонка 3 «Конвейера» — это компоненты `components/account/workspace/*`,
подключённые к другому источнику данных:
`components/admin/pipeline/pipeline-source.ts`. Отличия от кабинета:

| | кабинет | «Конвейер» |
| --- | --- | --- |
| чьи проекты | владельца сессии | выбранного пользователя, включая архивные |
| служебная папка `options` | скрыта | видна |
| чат | со стороны клиента | со стороны команды |
| разделы `?tab=` | есть | нет, список целиком |
| мутации файлов | все | никаких |
| пауза | да | да (тот же тумблер) |
| описание проекта | только чтение | **запись** — это как раз то, что команда пишет клиенту |
| параметры обработки | правит | не открывает |
| расшаривание | да | нет — это дело владельца |

Это самое удачное архитектурное решение в UI-части: два экрана с разными
правами и разными адресами, но один код рабочей области. Контракт источника —
`WorkspaceSource` в `components/account/workspace/types.ts`.

## Оболочка: `WorkspaceShell`

`components/account/workspace-shell.tsx` (~600 строк) — общая оболочка кабинета
и админки.

- боковая панель: свёрнутая 72px / развёрнутая 248px / минимум 200px; ниже 150px
  при перетаскивании защёлкивается в свёрнутую; ширина тянется `ResizeGrip`;
- разделы проектов — плоские кнопки, все на `/account/projects?tab=`;
- свёртка «Админка» появляется только у `role === ADMIN`;
- баланс, аватар с инициалами, переключатель RU/EN, выход;
- счётчики разделов — `useProjectCounts`, обновляются по событию
  `ffworks:projects-changed`;
- мобильно — выезжающее меню.
