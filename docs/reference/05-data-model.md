# 05 — Модель данных

PostgreSQL. Схема — `db/schema.sql` (идемпотентная, можно гонять на живой базе),
изменения — `db/migrations/*.sql`. ORM нет.

> Полный список таблиц с колонками, типами и размерами, снятый с живого
> сервера, собирается командой `npm run db:schema-doc` в `docs/DB_SCHEMA.html`
> (в репозитории его нет, он в `.gitignore`). Этот документ объясняет смысл
> полей, страница показывает фактическое состояние. Расхождения между ними
> означают, что документ отстал.

Все первичные ключи — `TEXT` с UUID внутри (`randomUUID()` из Node), кроме
`storage_changes.seq` (`BIGSERIAL` — нужен монотонный порядок) и составных ключей.

## 2. Люди и доступ

### `users`

| Поле | Смысл |
| --- | --- |
| `id`, `full_name`, `email` (уникальный) | базовое |
| `password_hash` | **nullable** — у OAuth-аккаунтов пароля нет |
| `auth_provider` | `local` \| `google` |
| `provider_account_id` | Google `sub`. Частичный уникальный индекс `(auth_provider, provider_account_id) WHERE provider_account_id IS NOT NULL` — один `sub` соответствует одному пользователю, но NULL может быть у многих |
| `role` | `USER` \| `ADMIN` |
| `is_active` | аккаунт не заблокирован. **К автоматизации отношения не имеет** |
| `must_change_password` | ставится при сбросе пароля админом и при создании аккаунта через приглашение |
| `contact_name` | имя, которым человек подписывается при локальной обработке. По нему группируется статистика (`description.contact`). NULL → берём `full_name` |
| `balance_cents` | баланс, пока только показывается; пополнение — заглушка |
| `drive_folder_id` | наследие Google Drive |
| `automation_enabled` | **гейт конвейера**, ставит админ. По умолчанию `TRUE`: гейт нужен, чтобы кого-то исключить. Гасит слежение за всеми проектами пользователя, не меняя флаги самих проектов |

Два разных «включено» — намеренно: `is_active` про аккаунт,
`automation_enabled` про обработку.

### `project_members`

`PRIMARY KEY (project_id, user_id)`, `role IN ('viewer','editor','full')`.

**Владельца здесь нет.** Он живёт в `projects.user_id`. Строка на владельца
создала бы два ответа на вопрос «чей это проект». `invited_by` нужен, чтобы
владелец видел в диалоге «Поделиться», откуда взялся человек, которого он сам не
приглашал.

### `share_contacts`

`PRIMARY KEY (user_id, email)`. История получателей диалога «Поделиться»: кому
этот человек уже давал доступ. Владелец списка — **приглашающий**, поэтому
подсказки одинаковы в кабинете и в админских «Папках пользователей» (диалог там
тот же). Пишется сервером после удавшегося приглашения
(`POST /api/projects/:id/members`), читается и чистится через
`/api/account/share-contacts`.

Ключ — почта, а не `user_id`: приглашают адрес, аккаунт под ним заводит сам роут.
`full_name` — снимок имени на момент приглашения, подпись в выпадающем списке;
обновляется при следующем приглашении. Хвост списка режется до 100 строк —
это подсказка, а не адресная книга. Правила — [BACKEND_PLAN §8.2в](../BACKEND_PLAN.md).

### `machine_tokens`

Токены `mch_…`, хранится только `token_hash` (SHA-256). Модель — «один токен,
много машин». `project_id` необязателен: заполнен — токен заскоупен на один
проект. Отзыв (`revoked_at`) отзывает и все машины, ходившие под токеном.

### `remote_computers`

Парк машин. Два способа появиться:

- админ создаёт вручную → свой токен `rc_…`, `registered_token_id IS NULL`;
- машина приходит с `mch_…` и своим `machine_uuid` → заводит себя сама,
  `registered_token_id` указывает на токен.

`machine_uuid` — генерируется машиной один раз при первом запуске. Hostname для
этого не годится: дефолтные имена маков совпадают, а на совпадении ломается архив
статистики — две машины пишут в один объект и заливка затирает строки.

Три разных отметки времени, сводить нельзя:

| Поле | Значит |
| --- | --- |
| `last_seen_at` | любое обращение со своим UUID |
| `last_claim_at` | воркер опрашивает очередь |
| `last_heartbeat_at` | пульс |

Машина может быть на связи и синхронизировать файлы, но обработку не вести.
Онлайн — пульс в пределах `REMOTE_COMPUTER_ONLINE_MS = 90 000`.
Уникальный индекс по `machine_uuid` — только среди неотозванных: отозвав
компьютер, ту же машину можно завести заново.

## 3. Проекты и файлы

### `projects`

| Поле | Смысл |
| --- | --- |
| `user_id` | **владелец** |
| `client_id` | логическая группировка в интерфейсе. На раскладку ключей в R2 не влияет |
| `group_name` | `personal` \| `shared` \| `tools` \| `archive` |
| `is_paused` | **единственный тумблер слежения**. Зеркало `options/folderState.json` (`enabled = NOT is_paused`); обоими хранилищами владеет `lib/project-automation.ts#setProjectPaused` |
| `is_archived`, `archived_at` | архив — отдельно от `group_name`; обработчики такие проекты пропускают |
| `deleted_at` | мягкое удаление в корзину проектов |
| `drive_folder_id` | наследие Drive. Уникальный индекс среди не-NULL: сканирование Drive делало upsert по нему, и без индекса два параллельных запроса создавали дубли |
| `yougile_chat_id` | появляется лениво, при первом сообщении в чат |
| `chat_last_read_at` | отметка чтения **владельцем** |

Колонка `is_active` **удалена** миграцией `2026-08-13-pipeline-automation.sql`:
она дублировала смысл `is_paused` и была с ней сварена, из-за чего пауза и
автоматизация меняли друг друга. Поле `isActive` в ответах машинам осталось и
считается как `NOT is_paused`.

### `project_files` — каталог

Плоская таблица: `folder_path` + `name`, а не рекурсивные ссылки.

| Поле | Смысл |
| --- | --- |
| `is_folder` | папки тоже строки. `CHECK`: папка без `s3_key`, файл — обязательно с ним |
| `s3_key` | физический ключ в R2 |
| `name` | **логическое** имя, которое видит человек |
| `etag`, `content_hash` | версия объекта. Есть не во всех выборках: репозитории читают строку без них, путь записи — вместе, потому что клиенту после заливки нужно чем-то сравнивать копии |
| `origin_mtime` | mtime на машине-источнике (unix-секунды) |
| `uploaded_by` | **кто принёс файл**. Перезапись переносит атрибуцию на нового заливщика; записи машин парка (`rc_`) её не трогают. Отсюда конвейер берёт `description.contact` |
| `deleted_at`, `deleted_by` | корзина файлов |
| `last_seq` | последнее событие журнала по этой строке |

Ключевой индекс:
```sql
CREATE UNIQUE INDEX project_files_unique_name_idx
  ON project_files (project_id, lower(folder_path), lower(name))
  WHERE deleted_at IS NULL;
```
Имена уникальны без учёта регистра — как в файловых системах Windows и macOS.
Удалённые под ограничение не попадают, поэтому имя освобождается сразу.

### `storage_changes` — журнал

`seq BIGSERIAL` — монотонный курсор для всей базы, не для проекта.
`op IN ('put','delete','move')`, `event_id` уникальный (идемпотентность повторов),
`payload JSONB` (имя, путь, `isFolder`, `fileId`, `from`/`to` для перемещений).

`actor_user_id` — кто совершил запись. Нужен конвейеру: для папки виток запускает
не заливщик файла, а тот, кто снял `-` с имени, то есть актор move-события.

Окно хранения при чтении `delta` — 90 дней; запрос с курсором старше окна
получает `truncated: true` и должен перечитать дерево целиком.

### `storage_jobs` — фоновые работы

`kind IN ('copy','move','purge','recatalog')`,
`state IN ('queued','running','done','failed','cancelled')`, счётчики
`total`/`done`, `event_id` уникальный.

### `clients`

Логическая группировка проектов в интерфейсе. Ключей в R2 не меняет.

## 4. Чат

### `project_chat_messages` — актуальный

| `sender_type` | Откуда |
| --- | --- |
| `client` | с сайта, уезжает в YouGile через REST |
| `team` | из YouGile (вебхук или поллер) |
| `system` | зарезервировано |

`yougile_message_id` с уникальным частичным индексом — дедуп при повторной
доставке. `delivered` — доехало ли в YouGile.

Счётчик «не отвечено» **выводится из переписки**, а не хранится: сообщения
клиента после последнего ответа команды. Отметки «команда прочитала» в схеме нет
и не нужно — админка и YouGile это один и тот же чат с двух сторон.

### `project_messages` — legacy 🔧

Старая модель: `sender_role IN ('user','team')`, флаги `read_by_user` /
`read_by_team`. Используется только роутом `/api/projects/[id]/messages`, который
из интерфейса не вызывается, и запросом `listProjectsByOwner`, у которого нет ни
одного вызова.

### `project_media` — legacy 🔧

Наследие Drive-эпохи. Читается один раз, как fallback, в
`app/account/projects/[id]/page.tsx`, когда состояние R2 не загрузилось.

## 5. Инструменты

### `user_tools`

Экземпляры инструментов из каталога **кода** (`lib/tools/registry.ts`).

| Поле | Смысл |
| --- | --- |
| `tool_key` | стабильный ключ из каталога, менять нельзя |
| `settings JSONB` | настройки экземпляра; PATCH **сливает**, а не заменяет |
| `source JSONB` | подключённый источник: `projectId`, `folderPath`, человекочитаемый `label` |
| `sort_order`, `last_opened_at` | порядок и свежесть в списке |
| `deleted_at` | мягкое удаление |

Каталог в коде, а не в таблице: у инструмента есть интерфейс, значит появление
нового — всё равно деплой, а таблица добавила бы состояние «запись есть, кода
нет».

## 6. Конвейер

### `automation_scan_state` — синглтон (`id = 'singleton'`)

| Поле | Смысл |
| --- | --- |
| `is_running` | включено ли слежение. **В базе, а не в памяти процесса**: закрытая страница не останавливает конвейер, перезапуск возобновляет, все админы видят одно |
| `last_seq` | курсор событийной линии по `storage_changes` |
| `scanned_at` | когда цикл проверял последний раз — двигается на **каждом** тике |
| `last_created`, `last_error` | итог последнего тика |
| `sweep_interval_min` | период страховочного обхода; `0` = по таймеру не ходить. `CHECK`: 0 или 1..1440 |
| `swept_at`, `last_swept`, `last_sweep_error` | итог обхода. `swept_at` двигается всегда, включая ошибку: от него считается следующий срок |

Почему `scanned_at` пишется на каждом тике: раньше он писался только при сдвиге
курсора, то есть только когда в журнале были новые события. Поле, которое должно
доказывать, что конвейер жив, ровно этого и не доказывало.

### `tasks`

| Поле | Смысл |
| --- | --- |
| `source_key` | ключ элемента верхнего уровня в IN — файла или папки |
| `payload JSONB` | объект для обработки: `processingQueue`, шаги по ключам, `mainSearch`, `description`. **Внутри нет presigned URL и локальных путей** — задача может простоять час, а ссылка живёт минуты |
| `status` | `queued` → `claimed` → `running` → `done` \| `failed` |
| `claimed_by`, `claimed_at`, `lease_expires_at` | аренда; 15 минут, продлевается каждым `taskProgress` |
| `attempts` / `max_attempts` | по умолчанию 3 |

Три индекса под три разных вопроса:

```sql
-- дедуп: повторное событие по файлу не плодит вторую живую задачу
CREATE UNIQUE INDEX tasks_active_source_idx ON tasks (project_id, source_key)
  WHERE status IN ('queued','claimed','running');

-- обход спрашивает «была ли задача вообще» — включая done и failed
CREATE INDEX tasks_source_key_idx ON tasks (project_id, source_key);

-- сборщик протухших аренд на тике каждые 15 секунд
CREATE INDEX tasks_lease_idx ON tasks (lease_expires_at)
  WHERE status IN ('claimed','running');
```

Завершённые под ограничение дедупа не попадают — по файлу можно прогнать
обработку заново.

### `task_progress`

`PRIMARY KEY (task_id, step_id)`, `status IN ('running','done','error')`.
Самоочищается: задача завершилась — строки удаляются. Разбор падения идёт по
`tasks.error` и логам машины.

### `automation_settings` — синглтон

Общие словари: типы файлов с расширениями, цвета типов нод и типов данных,
пользовательские маски путей. Домены — в `domains JSONB`.

`revision` растёт на **каждую** запись, даже если содержимое не изменилось: это
счётчик для оптимистической блокировки (`UPDATE … WHERE revision = $base`), а не
хеш состояния.

Домен — **массив**, а не объект: порядок значим, `getFileTypeByExt` возвращает
первое совпадение. `id` записи не хранится: у дефолтов он человекочитаемый
(`video`), у пользовательских — nanoid, то есть на второй машине другой.
Идентичность во всей системе по имени.

## 7. Витрина

### `videos` и `ideas`

**Структурно идентичны**: `title`, `description`, `thumbnail`, `video_url`,
`duration`, `category`, `tags TEXT[]`, `is_published`, `sort_order`, таймстемпы.
GIN-индекс по `tags` у обеих. `category` помечен `@deprecated` — используется
`tags[0]`.

Две таблицы, два репозитория и два набора роутов с одинаковой логикой. Разбор —
[14](./14-improvements.md#2-videos-и-ideas--две-копии-одной-сущности).

### `tag_suggestions`

Подсказки тегов: `field_scope` + `value`, счётчик использований, индекс по
`(field_scope, lower(value))`.

## 8. Аналитика

### `visitor_events`

Одна строка на клиентскую навигацию. `user_id` — **мягкая** ссылка без FK, а
`user_email` / `user_full_name` денормализованы: удаление пользователя не должно
уносить историю посещений. `fingerprint` — короткий хеш `ip|UA|Accept-Language`,
группирует анонимные сессии.

### `processing_stats`

Архив обработок, залитый машинами. `PRIMARY KEY (item_id)` — ключ дедупа,
вставка `ON CONFLICT DO NOTHING`, строки иммутабельны. Поэтому файл архива можно
перечитывать сколько угодно раз и с любого места.

Поля: `schema_version`, `status`, `project_name`, `main_folder`, `cur_item`,
`in_type`/`out_type`, `registered_at`/`started_at`/`ended_at`, `out_sec`,
`render_sec`, `out_paths JSONB`, `total_cost NUMERIC(12,6)`, `machine`.

### `stats_import_state`

Курсоры импорта: по ключу объекта в R2 — сколько строк уже прочитано и какой был
`etag`.

### `storage_snapshots`

Суточные срезы состояний: `PRIMARY KEY (day, project_id)`, поля `files`, `bytes`,
`owner_id`.

**Внешних ключей нет намеренно** — история переживает удаление проекта и
пользователя. Гранулярность одна (проект × день); срез пользователя — `SUM` по
его проектам. Проекты в корзине не снимаются, иначе ряд «рост объёма» разошёлся бы
с плитками, где корзина исключена.

### `push_subscriptions`

Одна на браузер/устройство. `endpoint` уникальный. Мёртвая подписка (404/410 от
push-сервиса) удаляется автоматически.

## 9. Инварианты, которые легко сломать

1. **Строка каталога и запись в журнал появляются вместе.** Весь путь записи
   идёт через `withTransaction`. Иначе клиент не узнает об изменении.
2. **Байты в R2 без строки каталога — сирота.** Удалить их клиенту нечем:
   `delete` работает по `file_id`. Поэтому `deleteOrphanUpload` убирает объект
   при отказе, который повтором не лечится (400 — плохое имя, 409 — занятое), но
   **не** убирает при неизвестной ошибке: клиент повторит `notify` тем же ключом,
   и доехавшие гигабайты пригодятся.
3. **Три сайдкара закреплены по имени и месту.** `folderState.json`,
   `options.json`, `description.md` внутри папки `options` в корне проекта. Сайт
   читает их по фиксированному ключу; уведи объект с места — тумблер и настройки
   перестанут читаться при целом и на вид исправном файле, без единой ошибки.
   Перезапись содержимого при этом разрешена.
4. **`options` — обычная папка.** Её содержимое создаётся, переименовывается и
   удаляется как любое другое; закреплены только три имени выше. В кабинете папка
   скрыта фильтром **на стороне вида**, а не выборки.
5. **Одна активная задача на элемент IN.** Держится частичным уникальным
   индексом, не кодом.
6. **`revision` словарей растёт на каждую запись.** Клиент, приславший
   устаревший `revision`, получает 409, а не молча перетирает чужую правку.
7. **`item_id` архива статистики иммутабелен.** На этом стоит вся
   переигрываемость импорта.
