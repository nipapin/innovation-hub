# Редактор титров по дорожкам персонажей — техническая документация

**Что это.** Инструмент в кабинете (`/account/projects?tab=tools`), который открывает папку
задачи из хранилища проекта и даёт человеку вычитать машинный результат: поправить
распознанный текст, тайминги, перенести реплики, приписанные не тому персонажу, вычитать
перевод. Работает **только онлайн**: папка проекта в R2 — единственное место, где лежат
файлы, ничего не скачивается и не зеркалится.

**Границы.** Инструмент не озвучивает, не переводит (перевод приходит готовым от обработки),
не рендерит видео и не запускает обработку. Он правит один документ в одной папке.

**Соседние документы.**

| документ | о чём |
|---|---|
| [DIALOG_FORMAT.md](./DIALOG_FORMAT.md) | **нормативный** контракт формата `dialog.json`, общий с локальным редактором в программе. При расхождении с этим файлом прав он |
| [TOOLS_SRT_EDITOR_PLAN.md](./TOOLS_SRT_EDITOR_PLAN.md) | проектное решение, статус пунктов, что ещё не сделано |
| [VOICE_OVER.md](./VOICE_OVER.md) | второй инструмент над тем же документом — озвучка: что он взял из этого каркаса и что добавил своего |
| [TOOLS_VOICEOVER_PLAN.md](./TOOLS_VOICEOVER_PLAN.md) | следующий инструмент — озвучка: он работает с тем же документом и переиспользует этот каркас |
| [TOOLS_DEV_GUIDE.md](./TOOLS_DEV_GUIDE.md) | как вообще делается инструмент раздела: реестр, экземпляр, точки подключения к данным, дизайн-база |
| [STORAGE_API.md](./STORAGE_API.md) | `tree` / `presign` / `notify`, которыми инструмент ходит в хранилище |

# Часть I. Как устроен инструмент

## 1.1. Карта кода

Разделение не «файлы поудобнее», а условие переносимости: то же поведение позже
воспроизводится в локальном редакторе программы, и всё, что не про интерфейс, переезжает
как есть. Признак прост: файл, который импортирует что-то из `components/`, переносу не
подлежит.

**Чистая логика — [lib/tools/dialog/](../lib/tools/dialog/), без React и без DOM.** Общая для

## 1.2. Что читается из папки и какими запросами

Порядок при открытии задачи:

1. **Дерево папки.**
   `GET /api/storage/v1/tree?projectId={id}&prefix={folderPath}`
   Возвращает **всё поддерево** папки задачи: и файлы в корне, и содержимое папок дорожек.
   У каждой записи есть `folderPath`, `name`, `isFolder`, `s3Key`, `sizeBytes`, `updatedAt`.
2. **Документ.** Среди записей ищется файл с именем `dialog.json` и `folderPath`, равным
   папке задачи. Содержимое читается через
   `GET /api/projects/{projectId}/drive/files/{fileId}`.

   **Не нашли — задача не отказывает, а собирается.** Документ — производная от папки: дорожки
   видны по подпапкам, реплики и тайминги лежат в титрах, языки читаются из имён файлов. Всё
   это инструмент собирает сам (`lib/tools/dialog/build-doc.ts`) и записывает через
   `POST /api/account/tools/{id}/document` — условной записью `If-None-Match: *`, чтобы двое,
   открывшие задачу одновременно, не записали два разных документа. Обработке остаётся
   разложить папку и сделать прокси; ноды под документ и пики ей не нужны.

   Сборка не запускается сама: она пишет файл в чужую папку, и человек сначала видит, что
   нашлось, и выбирает язык оригинала — из имён файлов его не узнать. Чего сборка не знает:
   имён персонажей и диаризации. Дорожки называются номерами папок, `origin.name` пустой, и
   «восстановить имена» честно ответит, что восстанавливать нечего.
3. **Разбор и валидация** (§2.2.4 ниже). Отказ — задача не открывается, с причиной.
4. **Медиа и волны.** Пути из документа относительны папке задачи; они склеиваются с
   `folderPath` и ищутся в дереве по точному совпадению `folderPath` + `name`. Для найденного
   `s3Key` берётся подписанная ссылка:
   `POST /api/storage/v1/presign` c `{ projectId, method: "GET", s3Key, ttlSec: 3600 }`.

Подписанная ссылка ведёт прямо в хранилище, а не через наш роут скачивания, по одной
причине: плееру нужен `Range`, иначе перемотки нет — он умеет только доиграть скачанное.

Что именно грузится по ссылкам:

| источник | когда | зачем |
|---|---|---|
| `media.video` | всегда; путь не сошёлся — видео берётся из корня папки подбором | `<video>`: кадр, звук, часы |
| `media.peaks` | всегда; поля нет — волна ищется по имени рядом с источником | волна на линейке и на дорожках без своих пиков |
| `tracks[].peaks` | то же для стема дорожки | своя волна дорожки |
| `tracks[].audio` | только когда дорожка в `solo` | звук дорожки персонажа |

**`media.mix` инструмент не проигрывает** — только показывает в подписи «Звук превью».
Отдельный файл микса как источник звука и часов ещё не подключён (см. §5).

**Волна считается сама, если её в папке нет.** Путь из документа старше всего; нет пути —
волна ищется рядом с источником по имени (`proxy.mp4` → `proxy.peaks.json`,
`01/audio.wav` → `01/audio.peaks.json`). Нет и файла — инструмент считает волну сам, **в фоне**:
титры и тайминги готовы сразу, а декодирование идёт по одному файлу за раз и дорисовывает
дорожки по мере готовности. Считает Web Audio (`lib/tools/dialog/peaks-compute.ts`) в моно на
8 кГц — при 50 парах в секунду это 160 сэмплов на столбик, а память не улетает на десятиминутном
материале. Посчитанное уезжает в папку через `PUT /api/account/tools/{id}/peaks` (узкий канал:
только `*.peaks.json`, только в папку задачи, разрешён и читателю), поэтому во второе открытие
задачи считать уже нечего. Не записалось — не авария: в этом сеансе волна нарисована, в
следующий посчитается заново.

**Видео ищется, а не берётся по имени.** Имя исходника контрактом не закреплено: обработка
кладёт в корень папки задачи то, что пришло от заказчика, а `media.video` может отставать или
не быть вовсе. Поэтому путь из документа — подсказка: не сошёлся — инструмент берёт видео из
**корня папки задачи** (`pickVideoEntry` в `use-task-folder.ts`). Кандидат — файл с типом
`video/*` или расширением `.mp4 .m4v .mov .webm .mkv .avi .mxf`; расширение проверяется наравне
с типом, потому что у файла, попавшего в хранилище мимо браузера, `contentType` пустой.

Порядок предпочтений — **прокси → `mp4` → остальное**, внутри группы по имени, чтобы выбор не
зависел от порядка строк каталога. Прокси (слово `proxy`, `preview`, `прокси` или `превью`
отдельным куском имени) старше мастера не ради экономии трафика: мастер рядом может оказаться
ProRes или HEVC, которых браузер не покажет вовсе, так что это условие того, что кадр вообще
будет. Параметры, с которыми обработка обязана его собирать, — в репозитории программы,
`fs.manager.tauri/flows/SRT_EDIT_ON_SITE.md` §5.
Глубже корня не ищем: там дорожки и сырьё, и видео оттуда было бы не тем файлом. Документ при
этом не правится: `media.video` принадлежит контракту с программой, и переписывать его своей
догадкой инструмент не вправе.

**Кадра нет — сказано, почему.** Раньше на месте кадра стояла одна надпись «в папке не
найдено», и её же человек видел, когда файл лежал на месте, а ссылку не выдало хранилище.
Теперь состояния разделены (`TaskVideo`, `videoNoticeText`):

| состояние | когда | что написано |
|---|---|---|
| `none` | ни поля в документе, ни видео в папке | «Видео в папке нет — тайминги и текст правятся и так» |
| `missing` | документ называет файл, а в папке нет ни его, ни другого видео | «Видео `{file}` из документа в папке не найдено…» |
| `loading` | файл нашли, ссылку подписываем | «Видео открывается…» |
| `unavailable` | файл есть, `presign` ссылку не выдал | «Видео `{file}` в папке есть, но хранилище не выдало на него ссылку» |

`unavailable` — это, как правило, отказ по ключу: `presign` требует, чтобы `s3Key` начинался с
`projects/{storage_owner_id}/{projectId}/`, а роут скачивания файла такой проверки не делает.
Отсюда и картина, по которой этот отказ узнаётся: `dialog.json` открылся, а видео и волны — нет.

## 1.3. Модель данных в памяти

Разобранный документ — обычный объект, не класс. Три правила, которые важнее остальных:

- **время только в целых миллисекундах.** Секунд с плавающей точкой в модели нет: `26.27`
  в одной реализации станет `26.269999999999996` в другой, и сравнение таймингов начнёт
  врать;
- **реплики всегда отсортированы** по `startMs`, затем `trackId`, затем `id`. Порядок
  поддерживается каждой операцией, а не восстанавливается перед записью;
- **неизвестные поля не теряются.** Всё, чего модель не знает, складывается в `extra` на
  уровне документа, дорожки и реплики и возвращается на место при записи. Без этого сайт
  вырезал бы из файла поля, которые добавила программа.

Состояние интерфейса — `solo`, `mute`, `shy`, видимость волны, высота дорожек, масштаб,
выбранный язык, раскладка клавиш — **в документ не пишется** (§2.8 контракта формата). Живёт
в `localStorage` по ключу инструмента.

## 1.4. Часы и звук

**Часы одни.** Источник времени — `<video>`: таймлиния, список и титры поверх кадра читают
`currentTime` и рисуют по нему. Второго источника времени нет намеренно — это рассинхрон,
который потом невозможно поймать. Если видео в папке нет, часы ведёт программный таймер на
`requestAnimationFrame`; редактор при этом полностью работоспособен, просто без кадра.

Время наружу отдаётся подпиской, а не состоянием React: при 60 кадрах в секунду `setState`
перерисовывал бы весь редактор вместе со списком реплик. Подписываются только курсор, часы
транспорта и титры на кадре.

**Что звучит:**

| состояние | звук видео | дорожки персонажей |
|---|---|---|
| ни `solo`, ни `mute` | звучит | молчат |
| есть `solo` | заглушён | звучат те, что в `solo`, у которых есть `tracks[].audio` |
| `solo` на дорожке без `audio` | заглушён | тишина, и подпись это прямо говорит |
| есть `mute`, `solo` нет | заглушён | звучат все, кроме выключенных, у которых есть `audio` |
| `mute` на всех дорожках | заглушён | тишина, и подпись это прямо говорит |

`solo` старше `mute`: включённый `solo` отвечает на вопрос «что я хочу слышать»
целиком, и выключенное раньше этот ответ не правит — иначе пришлось бы помнить,
что где-то ниже осталась нажатая `M`. Оба режима глушат микс видео: не заглушить
его — значит подмешать к стему тот же голос второй раз.

Аудио дорожки играется отдельным `<audio>` на дорожку, время подтягивается к часам видео:
при расхождении больше **40 мс** источник ставится на место, но не чаще чем раз в 250 мс —
каждая правка `currentTime` слышна щелчком. Порог 40 мс — половина типичной длительности
слога: меньше человек не слышит, больше уже эхо.

## 1.5. Таймлиния

**Координаты.** Одна пара функций, через которую проходит всё:

```
msToX(ms, pps) = ms / 1000 * pps
xToMs(x, pps)  = x / pps * 1000
```

`pps` — пикселей на секунду, от 12 до 320. Горизонтальная прокрутка — обычный скролл
контейнера, поэтому «левый край окна» в координатах не участвует: полотно рисуется целиком,
браузер показывает его часть.

**Зум:** ползунок (шкала логарифмическая), кнопки ±35 % и `Cmd`/`Ctrl`/`Alt` + колесо —
плавно, секунда под курсором остаётся на месте.

**Линейка.** Шаг подписей выбирается из ряда 100 мс / 250 / 500 / 1 с / 2 / 5 / 10 / 30 /
1 мин / 5 / 10 — первый, при котором подписи не ближе 60 px. Так шкала читается одинаково на
любом зуме.

**Волна.** Рисуется на canvas, и только видимый кусок полотна: десять минут при 320 px/с —
это 224 000 пикселей, столько не рисует ни один canvas. Перерисовка при скролле, зуме, смене
высоты дорожки и цвета. Столбиками по одному на пиксель, размахом вверх от нижнего края —
по центру дорожки лежат клипы, и волна под ними пропадала. Своя волна дорожки — её цветом,
общая — серым и приглушённо, с пометкой «общая» в шапке.

**Клипы** — элементы DOM поверх волны: им нужен текст и ручки. Минимальная ширина 3 px,
чтобы короткая реплика не исчезала; ручки границ по 6 px, и на клипе уже 18 px их нет вовсе
— иначе за него невозможно взяться.

**Инструменты:**

| инструмент | клавиша по умолчанию | что делает |
|---|---|---|
| выделение | `V` | выбор, сдвиг по времени, растягивание границ |
| создание | `C` | протяжка по пустому месту дорожки создаёт реплику |
| разрез | `B` | клик по клипу режет его в точке курсора |
| перенос | `M` | тащить вверх-вниз: только смена дорожки, тайминги не меняются |
| объединение | `J` | клик по соседней реплике той же дорожки объединяет их |

Клавиши привязаны к **физической кнопке** (`event.code`), а не к букве: на русской
раскладке та же кнопка даёт «и» вместо «b». Переназначаются в настройках инструмента.
Клавишу можно зажать: пока держите — инструмент активен, отпустили — вернулся предыдущий
(порог 260 мс).

**Панель дорожек** слева. В её шапке три кнопки: добавить дорожку в конец, режим
перестановки и режим удаления. Перестановка и удаление — именно режимы: в них кнопки
`mute` / `solo` / `shy` в строках подменяются на стрелки или на корзину. Так узкая строка не
растёт, а рука, потянувшаяся к стрелке, не попадает в корзину. `Esc` выходит из режима.

Удаление дорожки уносит её реплики (они уходят в `removed`, иначе повторный прогон обработки
вернёт их обратно), поэтому непустая дорожка спрашивает подтверждение и называет число реплик.
Перестановка меняет местами **номера** двух дорожек, а не переписывает `no` подряд: номер — это
имя папки сырья, и ссылки в `origin` должны продолжать сходиться.

**Прилипание** — к границам реплик той же дорожки, допуск 8 px. В пикселях, а не в
миллисекундах: на любом зуме «рядом» должно означать одно расстояние на экране.

**Миникарта** ([`timeline-minimap.tsx`](../components/account/tools/shared/timeline-minimap.tsx))
— весь материал в одну строку, в пустом месте панели между кнопками инструментов и
масштабом. Общая для обоих инструментов раздела: собирает её каркас таймлинии, а место в
строке выбирает инструмент — блоки ему передаёт он же (`overview`), потому что каркас не
знает, титры там или тейки.

Появилась из простого: полотно длиннее окна в десятки раз, и добраться с начала в конец
можно было только колесом с зажатым `Shift`. На карте видно всё сразу — блоками реплики
(цветом своей дорожки, скрытые дорожки не показываются: карта обязана совпадать с тем, что
под ней), приглушённой волной общий звук, рамкой — какой кусок сейчас на экране. Рамку
тащат мышью, и это единственный способ попасть в конец одним движением; клик мимо рамки
переносит окно серединой на это место.

Своей ширины у неё нет — сколько осталось места, столько и занимает, и этой же шириной
задаётся масштаб карты. Поэтому ширина меряется наблюдателем у самого элемента, а не
считается от окна. В узкой панели карта сжимается первой: она удобство, а кнопки —
работа. Рисование на canvas, положение рамки и курсора — стилями по подписке на окно
просмотра: прокрутка идёт покадрово, и рендер дерева React на каждый кадр съел бы всё.

## 1.6. Правки и отмена

Всё, что делает человек, выражается операциями над документом — чистыми функциями
`dialog-doc.ts`: правка текста и перевода, тайминги, перенос на дорожку, создание, удаление,
разрез, объединение реплик, переименование дорожки, цвет дорожки, добавление, перестановка и
удаление дорожки, добавление и удаление языка, слияние дорожек, восстановление из сырья.

Отмена — стек снимков документа, глубина 100. Одно движение человека = один шаг отмены:
протяжка клипа даёт правку на каждый кадр мыши, и все они склеиваются признаком жеста,
иначе одно «отменить» возвращало бы клип на пиксель назад шестьдесят раз. Правка текста
уходит в документ по потере фокуса, а не на каждую букву, по той же причине.

## 1.7. Сохранение

Кнопки «сохранить» нет: правки уходят в папку сами через **1,2 с затишья**, но не позже чем
через 8 с непрерывной работы. `Cmd`/`Ctrl`+`S` пишет немедленно. Индикатор в топбаре
показывает состояние: сохранено · сохранение… · есть несохранённые правки · не сохранилось.

Записывает **сервер**, одним запросом
`PUT /api/account/tools/{toolId}/document` с телом `{ doc, baseRevision }`:

1. проверяет право правки в проекте (роль не ниже `editor`);
2. разбирает присланный документ — невалидный до хранилища не доходит;
3. читает то, что лежит в папке **сейчас**, вместе с ETag;
4. если ревизия в папке не та, от которой правили, — сливает версии (§8 контракта);
5. проставляет `revision` = предыдущая + 1, `updatedAt`, `updatedBy` (почта правившего),
   `producer` = `innovation-hub/srt-editor 0.1`;
6. пишет **условной записью** по `If-Match`. Не совпало — попытка сначала, до трёх раз,
   дальше клиент получает `409` и пробует сам;
7. обновляет строку файла в базе тем же путём, что все файлы проекта, поэтому журнал
   изменений и курсор синхронизации остаются верными. `uploaded_by` файла при этом не
   меняется: сохранение документа не должно переносить `contact` задачи.

Читать-сливать-писать на сервере, а не тремя запросами из браузера, нужно затем, чтобы между
чтением и записью не оставалось окна, в которое влезет вторая вкладка.

**Правила слияния** (когда документ тронули со стороны — другая вкладка, другая машина,
повторный прогон обработки):

- реплика есть только у одной стороны → берётся, если её нет в `removed` у другой;
- реплика есть у обеих → выигрывает та, у которой больше `rev`;
- `rev` равны, содержимое разное → берётся наша, и выжившая помечается
  `status: "conflict"`: человек должен увидеть, что чужую правку перекрыли;
- дорожки — объединение по `id`, имя и цвет из документа с большей `revision`;
- `removed` — объединение, и всё, что в нём, из реплик выбрасывается;
- языки — объединение с сохранением порядка;
- `revision` результата — `max(наш, их) + 1`.

**Канонический вид файла.** Порядок ключей фиксированный, отступ два пробела, перевод строки
в конце, реплики отсортированы, языки внутри `tr` по алфавиту, пустые необязательные поля не
пишутся. Это не вкус: две реализации на одном документе обязаны дать одни и те же байты,
иначе любой diff превращается в кашу, а проверка «открыл → сохранил → файл тот же» перестаёт
что-либо значить.

## 1.8. Экспорт

Кнопка «Экспорт» — меню с тремя быстрыми выгрузками и расширенным окном. Файл уходит **в
браузер, на машину человека**; папку `exports/` внутри задачи инструмент пока не наполняет
(см. §5).

| пункт | что получается |
|---|---|
| **Выбранная дорожка** | титры выбранного персонажа на текущем языке. Неактивен, пока дорожка не выбрана |
| **Всё — архивом** | все дорожки на **всех** языках документа: оригинал и каждый перевод |
| **Все дорожки — одним файлом** | обычные титры к видео: все реплики вперемешку по времени, текущий язык |
| **Расширенный экспорт…** | окно: языки, формат, раскладка, чекбоксы дорожек |

Формат быстрые пункты берут из настроек инструмента и показывают его подписью справа
(`SRT`, `SRT+BOM`, `VTT`) — информация не основная, но без неё пункт молча отдаёт WebVTT
человеку, который ждал SRT. Язык — из переключателя в топбаре, кроме «Всё — архивом»:
«выгрузить всё» значит всё, а не «всё на том языке, который сейчас открыт».

### Расширенное окно

Выгрузка задаётся тремя независимыми осями:

- **языки** — кнопками-переключателями сверху: нажат — выгружается, отжат — нет. Оригинал
  и каждый перевод отдельно, любое сочетание. Не «или-или», потому что оригинал вместе с
  двумя переводами — обычное дело, и выбор одного значения заставлял бы открывать окно трижды;
- **раскладка** — все дорожки в один файл или по файлу на дорожку;
- **дорожки** — чекбоксами, с «выбрать все» и «снять».

Внизу окна — что именно получится: имя файла или архива, число файлов и реплик. Кнопка
неактивна, пока не выбрана ни одна дорожка или ни один язык.

### Форматы

| формат | что получается |
|---|---|
| `srt` | SRT, UTF-8 без BOM |
| `srt-bom` | то же, с BOM: часть монтажных программ без него читает кириллицу как «кракозябры» |
| `vtt` | WebVTT |

BOM ставится **в каждый** файл выгрузки, включая каждый файл внутри архива.

### Имена файлов

Одно правило на все случаи: **один файл отдаётся файлом, несколько — архивом**, а внутри
архива язык становится папкой. Так набор из трёх языков и пяти дорожек не превращается в
пятнадцать имён, различающихся суффиксом, — и раскладка совпадает с описанной для `exports/`.

```
Notting_Hill.en.srt              все дорожки одним файлом, один язык
Notting_Hill.01-Anna.es.srt      одна дорожка, один язык
Notting_Hill.zip                 всё остальное:
  en/01-Anna.srt
  en/02-Bob.srt
  es/01-Anna.srt
  es/02-Bob.srt
  fr/01-Anna.srt
  fr/02-Bob.srt
```

Код языка в путях — из документа: у переводов это ключ из `languages.targets`, у оригинала —
`languages.original`. Номер дорожки идёт впереди имени персонажа, чтобы файлы сортировались
так же, как дорожки на таймлинии, а не по алфавиту. Из имён убирается всё, что распаковщик
может понять как путь; кириллица остаётся — архив помечен как UTF-8.

**Нумерация внутри файла своя.** Титры нумеруются по порядку в этом файле, а не по `id` и не
по номеру в документе: выгрузка одной дорожки начинается с `1`, как того ждёт любой плеер.

**Архив собирается без сжатия** (метод `store`). Титры — текст по десятку килобайт, сжатие им
почти ничего не даёт, а класть ради этого в зависимости архиватор несоразмерно: `store` — это
заголовок, данные и опись, полсотни строк чистого кода, которые переедут в локальный редактор
вместе с остальной логикой. Ограничения — 4 ГБ и 65 535 файлов, для титров недостижимо.

## 1.9. Восстановление из сырья

Правки живут в `dialog.json`, а исходные `{NN}/orig.srt` и `{NN}/{lang}.srt` инструмент
никогда не трогает. Значит на вопрос «что здесь было до моих правок» можно ответить честно, а
не «предыдущей версии не сохранилось».

**Это не отмена и не история версий.** Отмена работает в пределах сеанса и знает каждый шаг;
восстановление возвращает машинный результат — то, с чего начиналось, — и про промежуточные
состояния не знает. Само восстановление проходит через историю, поэтому `Cmd/Ctrl+Z` возвращает
документ к состоянию до сброса.

Кнопка со стрелкой в топбаре — меню из двух пунктов:

| пункт | что делает |
|---|---|
| **Восстановить всё** | все дорожки, все языки, текст, тайминги, исходные дорожки и удалённые реплики. Спрашивает подтверждение |
| **Расширенное восстановление…** | окно с пределами — как расширенный экспорт, только наоборот |

В окне выбирается **что**, **какие языки** и **какие дорожки**. Пунктов «что» пять, и у
каждого рядом стоит число — сколько записей изменится при текущих пределах:

| пункт | что возвращает | откуда |
|---|---|---|
| текст титров | распознанный текст выбранных языков | `{NN}/orig.srt`, `{NN}/{lang}.srt` |
| тайминги | исходные начало и конец реплики | `{NN}/orig.srt` |
| имена дорожек | имя, которое дала обработка | `tracks[].origin.name` |
| исходная дорожка | перенесённые реплики — туда, куда их приписала автоматика | `cues[].movedFrom` |
| удалённые реплики | то, что было удалено из документа | `{NN}/orig.srt` |

Числа рядом с пунктами — не украшение: без них окно читается как сломанное. Галочки стоят,
кнопка серая, и непонятно, то ли она не работает, то ли восстанавливать правда нечего. Ноль
у пункта отвечает на это сразу, до нажатия. Сырьё для этого читается при открытии окна, а не
при нажатии.

**Имена дорожек — особый случай.** В сырье папки их нет вовсе: `{NN}/orig.srt` — это титры,
а не список персонажей. Поэтому машинное имя должно лежать в самом документе, в
`tracks[].origin.name`, и записать его обязана обработка. Нет поля — восстановление честно
покажет ноль, а не вернёт что попало.

**Как реплика находит своё сырьё.** По `origin`: `file` и `index`. Оригинал берётся из
`origin.file`, перевод — по раскладке папки, `{NN}/{lang}.srt`, с тем же `index`. Отсюда два
следствия:

- восстановление работает, только если папка следует раскладке §2.1 и `origin` заполнен. Файла
  нет — реплика попадает в счётчик «без сырья», и её никто молча не портит;
- **реплики, созданные человеком** (`origin.kind === "manual"`), сырья не имеют и не
  трогаются. Восстанавливать их не из чего, а удалять при «сбросить всё» было бы подменой
  смысла: человек просил вернуть машинное, а не вычистить своё.

**Имя файла сырья не обязано быть контрактным.** Имена в папке дорожки обработка задаёт
свободно — `original.srt`, `dialog_rus.srt`, `speaker_01_eng.srt`, — и требовать ровно
`orig.srt` значило бы отказывать в восстановлении из-за имени. Поэтому путь из документа —
первая попытка, а не единственная: не сошлось — файл ищется **в той же папке дорожки** по
языку в имени (`lib/tools/dialog/srt-files.ts`):

| ищем | чем берём | чего не делаем |
|---|---|---|
| оригинал | слово в имени (`original`, `orig`, `source`, `исходник`), затем язык из `languages.original` (`..._eng`), затем — единственный `.srt` в папке | не берём файл, названный чужим языком |
| перевод | только названный язык: код (`ru`, `pt-BR`), трёхбуквенный (`rus`), слово (`russian`, `рус`) | не берём файл со словом «оригинал» в имени и не берём наугад единственный `.srt` |

Язык должен быть отдельным куском имени — отбитым `-`, `_`, `.` или пробелом: `dialog_rus.srt`
распознаётся, `dialogRUS.srt` нет. Отличить в слитном имени язык от хвоста слова нельзя, а
ложное совпадение здесь дороже пропуска: подставить в реплику чужой текст хуже, чем сказать
«сырья не нашлось». По той же причине единственный `.srt` в папке годится за оригинал, но
никогда — за перевод.

Ключи в ответе остаются те, которые просили (`01/ru.srt`), даже когда файл нашёлся под другим
именем: реплики сопоставляются по `origin.file` и `index`, и подменять ключи настоящими
именами значило бы чинить поиск ценой сопоставления.

## 1.9.1. Версии документа

Живут в том же окне, что и восстановление: и то и другое отвечает на «вернуть как было».
Разница в том, что версия помнит и ручные правки, а сырьё знает только машинный результат.

Активная версия — всегда `dialog.json`: имя закреплено контрактом, и его же читает программа.
Отложенные лежат рядом в корне задачи — `dialog.v1.json`, `dialog.v2.json`, обычными файлами,
которые видно в папке.

Любое действие (`POST /api/account/tools/{id}/versions`) начинается с того, что текущий документ
откладывается в следующую свободную версию. Отсюда два действия в окне:

| действие | что происходит |
|---|---|
| **Собрать из папки заново** | текущий уходит в версию, на его место встаёт документ, собранный из папки прямо сейчас |
| **Вернуть в работу** | текущий уходит в версию, на его место встаёт выбранная старая |

У пересборки есть переключатель **«сохранить мои правки»**, включённый по умолчанию. Обычный
повод пересобрать — «в папку докинули перевод», и терять из-за нового языка всю вычитку не
должен никто. Работает это через слияние (§8 контракта) плюс дописывание недостающих переводов
(`mergeRebuild`): правленая реплика старше только что собранной по `rev`, а язык, которого в ней
не было, добавляется. Возможно всё это только потому, что сборка даёт репликам одни и те же id:
пересобрали ту же папку — получили те же ключи.

Вернувшаяся из удалённых реплика получает **новый `id`**: прежний остаётся в `removed` и
больше не воскресает. Удаление конкретной реплики зафиксировано, а это новая запись с тем же
содержимым.

Восстановление увеличивает `rev` каждой изменённой реплики и ставит `status: "auto"` — это
такая же правка, и слияние с чужой версией должно видеть, что наша сторона новее.

# Часть II. Вход: папка задачи в `OUT`

## 2.1. Раскладка и правила имён

```
OUT/                                   ← корень задач проекта (settings.sourceRoot)
  Notting_Hill/                        ← одна задача = одна папка = один материал
    dialog.json                        ← документ: дорожки, реплики, переводы, правила
    source.mp4                         ← кадр + общий звук
    mix.peaks.json                     ← волна общего звука
    01/                                ← папка дорожки: номер, не имя
      orig.srt                         ← сырьё: распознанный текст
      es.srt                           ← сырьё: перевод
      audio.wav                        ← только если стемы вообще есть
      audio.peaks.json                 ←   и тогда волна к ним
      voice/                           ← озвучка: её создаёт инструмент озвучки
    02/
      orig.srt
      es.srt
    exports/                           ← производное, обработка сюда не пишет
```

**Задача — папка первого уровня внутри `OUT`.** Именно её человек выбирает в меню
«проект → папка задачи», и её имя он видит. Имя исходника без расширения подходит,
`job_8f21ac` — нет.

**Имена файлов и папок:**

- UTF-8, без ведущих и хвостовых пробелов;
- без `/` и `\` внутри имени;
- регистр сохраняется, но полагаться на различие регистра нельзя: две задачи `Clip` и `clip`
  в одной папке — плохая идея;
- папка дорожки — две цифры с ведущим нулём: `01`, `02`, …, и это же значение стоит в
  `tracks[].no`.

**Почему папка дорожки — номер, а не имя персонажа.** Имя живёт в документе и меняется в
редакторе. Будь оно в пути, переименование персонажа двигало бы файлы и ломало ссылки.

**Промежуточных файлов в `OUT` быть не должно.** Аудио 16 кГц, `words.json`, разметка
спикеров живут в локальной рабочей папке обработки и вычищаются. Отсюда требование, чтобы
`dialog.json` был самодостаточным: редактор не увидит ничего, кроме этой папки.

## 2.2. `dialog.json`

Единственный обязательный файл. Источник правды: дорожки, реплики, переводы, правила
материала. Нормативное описание формата — [DIALOG_FORMAT.md](./DIALOG_FORMAT.md), здесь то
же, но с точки зрения «что положить на вход».

### 2.2.1. Пример целиком

```jsonc
{
  "format": "dialogDoc",              // ровно эта строка, иначе файл не наш
  "version": 1,                       // major формата
  "id": "dd_9f2c7a1e",                // id документа, непрозрачный
  "revision": 7,                      // счётчик версий файла
  "updatedAt": "2026-08-24T10:00:00.000Z",
  "updatedBy": "aleksey.ivanov@id.thesoul.io",
  "producer": "pipeline/dialogDocBuild 0.1",

  "media": {
    "video": "source.mp4",            // относительно папки задачи
    "mix": null,
    "peaks": "mix.peaks.json",
    "durationMs": 40000,
    "fps": 25
  },

  "languages": {
    "original": "en",
    "targets": ["es", "fr"]           // порядок = порядок колонок в редакторе
  },

  "rules": {
    "maxCps": 17,
    "maxTranslationRatio": 1.2,
    "minDurationMs": 400,
    "minGapMs": 80,
    "overlapWithinTrack": "forbid"
  },

  "tracks": [
    {
      "id": "t01",
      "no": 1,                        // = имя папки дорожки ("01")
      "name": "Anna",                 // имя персонажа
      "color": "#5B8DEF",
      "audio": null,                  // обычный случай: своего звука нет
      "peaks": null,
      "diar": { "engine": "sherpa-onnx 1.10.0", "speaker": "s0", "confidence": 0.86 },
      "voice": { "provider": null, "voiceId": null, "params": {} }
    }
  ],

  "cues": [
    {
      "id": "c_7f3a2b91",
      "trackId": "t01",
      "startMs": 26270,               // целые миллисекунды
      "endMs": 29190,                 // эксклюзивен
      "text": "So these guys just disappeared.",
      "tr": {
        "es": { "text": "Así que estos tipos simplemente desaparecieron.", "status": "draft" }
      },
      "status": "auto",
      "rev": 1,                       // +1 на каждую правку реплики
      "origin": { "kind": "auto", "file": "01/orig.srt", "index": 1, "speaker": "s0", "confidence": 0.62 },
      "note": "",
      "voice": { "takes": [] }

```

Рабочий эталон лежит в репозитории: [dialog.example.json](./dialog.example.json).

### 2.2.2. Поля документа

| поле | тип | обязательно | смысл и последствия |
|---|---|---|---|
| `format` | `"dialogDoc"` | **да** | ровно эта строка. Другое значение — отказ «не наш файл» |
| `version` | целое | **да** | major формата. Нет поля — отказ; значение больше 1 — отказ «документ новее инструмента» |
| `id` | строка | **да** | id документа. Непрозрачный: не парсить, не показывать человеку. Нет поля — отказ |
| `revision` | целое ≥ 0 | **да** | счётчик версий **файла**. По нему определяется, кто новее при слиянии. Нет поля или отрицательное — отказ. Нельзя сбрасывать при дописывании |
| `updatedAt` | ISO 8601 UTC | нет | когда файл записали последний раз |
| `updatedBy` | строка | нет | кто записал: почта человека или имя ноды |
| `producer` | строка | нет | чем записали, `имя/версия` |
| `media` | объект | нет | см. ниже; без него редактор откроется на одних репликах |
| `languages` | объект | нет | см. ниже |
| `rules` | объект | нет | правила материала; без него значения по умолчанию |
| `tracks` | массив | да, может быть пустым | дорожки персонажей. Нет ключа — считается пустым, и репликам некуда ссылаться |
| `cues` | массив | да, может быть пустым | реплики. Нет ключа — считается пустым: задача «текста ещё нет» |
| `removed` | массив | нет | что удалено человеком. Прививка от воскрешения при дописывании |

Любое поле верхнего уровня, которого здесь нет, **сохраняется** и записывается обратно.
Именно так в документе живёт, например, `mergedTracks`.

### 2.2.3. `media`, `languages`, `rules`, `tracks`, `cues`

**`media`** — где лежит материал. Все пути относительны папке задачи.

| поле | тип | обязательно | если отсутствует |
|---|---|---|---|
| `video` | путь | нет | кадр не показывается, остаются титры и таймлиния; часы ведёт программный таймер |
| `mix` | путь | нет | инструмент это поле пока только показывает в подписи |
| `peaks` | путь | нет | волны нет: линейка и клипы работают |
| `durationMs` | целое ≥ 0 | по контракту да | длина берётся по последней реплике; за концом видео пропадает серая зона на таймлинии |
| `fps` | число | нет | покадровый шаг недоступен, шаг ±100 мс |

**`languages`** — языки материала.

| поле | тип | обязательно | если отсутствует |
|---|---|---|---|
| `original` | код языка | по контракту да | считается `"und"` |
| `targets` | массив кодов | по контракту да (может быть пустым) | колонок перевода нет; человек добавит язык в редакторе, и он уйдёт в документ |

Коды — ISO-639-1 или BCP-47: `ru`, `es`, `pt-BR`. Порядок `targets` задаёт порядок кнопок
языков в топбаре. Переводы на язык, которого нет в `targets`, **сохраняются, но не
показываются** — иначе перевод пропадал бы при удалении языка из списка.

**`rules`** — правила **материала**, не настройки человека. Нарушения дают замечания, а не
отказ: файл мог прийти из другого прогона.

| поле | тип | по умолчанию | смысл |
|---|---|---|---|
| `maxCps` | число | 25 | знаков в секунду, выше которых титр не прочитать |
| `maxTranslationRatio` | число | 1.2 | во сколько раз перевод может быть длиннее оригинала |
| `minDurationMs` | целое | 250 | короче этого титр мигает |
| `minGapMs` | целое | 80 | зазор между соседними титрами |
| `overlapWithinTrack` | `"forbid"` \| `"warn"` | `"forbid"` | допустимо ли наложение реплик **одной** дорожки |

**`tracks[]`** — дорожка персонажа. Дорожку определяют её реплики, а не аудиофайл.

| поле | тип | обязательно | смысл |
|---|---|---|---|
| `id` | строка | **да** | непрозрачный id. Уникален в документе, иначе отказ |
| `no` | целое | **да** | номер = имя папки дорожки. Уникален, иначе отказ |
| `name` | строка | **да** | имя персонажа. Пусто — подставится `#1`, `#2` |
| `color` | `#RRGGBB` | нет | цвет метки. Пусто — раздаётся по кругу; человек меняет его в шапке дорожки, и выбор пишется в документ |
| `audio` | путь | нет | **обычно нет**: у дорожки персонажа своего звука не бывает |
| `peaks` | путь | нет | своя волна. Пусто — рисуется общая, приглушённо и с пометкой |
| `diar` | объект | нет | откуда взялась дорожка: `engine`, `speaker`, `confidence` |
| `origin` | объект | нет | чем дорожка была изначально: `kind` (`auto`/`manual`) и `name` — имя, которое дала обработка. **Единственный источник для восстановления имени**: в сырье папки имён дорожек нет |
| `voice` | объект | нет | задел под озвучку. **Сохранять как есть** |

**`cues[]`** — реплика.

| поле | тип | обязательно | смысл |
|---|---|---|---|
| `id` | строка | **да** | непрозрачный id. Уникален, иначе отказ |
| `trackId` | строка | **да** | ссылка на `tracks[].id`. Нет такой дорожки — отказ |
| `startMs` | целое ≥ 0 | **да** | начало |
| `endMs` | целое | **да** | конец, **эксклюзивен**: `[1000, 2000)` и `[2000, 3000)` не пересекаются. `endMs <= startMs` — отказ |
| `text` | строка | **да** | оригинал. Пустая строка допустима |
| `tr` | объект | нет | перевод по коду языка: `{ "es": { "text": "…", "status": "draft" } }` |
| `status` | `auto` \| `edited` \| `approved` \| `conflict` | нет | считается `auto` |
| `rev` | целое ≥ 1 | нет | счётчик правок **этой реплики**. Растёт на каждую правку, нужен слиянию |
| `origin` | объект | нет | откуда пришла: `kind` (`auto`/`manual`), `file`, `index`, `speaker`, `confidence` |
| `movedFrom` | строка | нет | id дорожки, на которой реплика была изначально: след ошибки автоматики |
| `note` | строка | нет | заметка человека |
| `voice` | объект | нет | задел под озвучку. **Сохранять как есть** |

`tr[lang].status` — `draft` \| `approved` \| `conflict`.

### 2.2.4. Валидация при открытии

Порядок фиксирован, чтобы обе реализации ругались на одно и то же. **Отказ** — задача не
открывается, с причиной; молча починить и записать обратно нельзя, это испортило бы файл у
второй стороны.

| проверка | результат |
|---|---|
| `format !== "dialogDoc"` | отказ: не наш файл |
| нет `version`, `id` или `revision`; `revision < 0` | отказ с именем поля |
| `version > 1` | отказ: документ новее инструмента |
| путь с `..`, ведущим `/` или буквой диска в `media.*` или `tracks[].*` | отказ с указанием пути |
| два `tracks[].id` совпали | отказ |
| два `tracks[].no` совпали | отказ |
| два `cues[].id` совпали | отказ |
| `cues[].trackId` не найден в `tracks` | отказ с id реплики |
| `startMs < 0`, `endMs <= startMs`, не число | отказ с id реплики |
| `endMs > media.durationMs` | замечание: длину могли записать неточно |
| `tr` содержит язык не из `languages.targets` | замечание: сохраняем, не показываем |
| нарушения `rules` | замечание, никогда не отказ |

`a..b.mp4` — не выход наверх: две точки внутри имени файла допустимы, проверяется именно
сегмент `..`.

## 2.3. `source.mp4` — видео

Здесь контракт упирается не в наши договорённости, а в плеер браузера.

**Требования:**

- контейнер и кодек, которые браузер играет. Практически — `mp4` с **H.264 + AAC**, либо
  `webm` с **VP9/AV1 + Opus**. `ProRes`, `DNxHR`, `HEVC` в `mp4`, `mkv` не откроются, и
  задача покажется без кадра;
- `-movflags +faststart`. Без него заголовок лежит в конце файла, и браузер не начнёт
  играть, пока не скачает всё целиком;
- звук внутри — это и есть «основная дорожка», её слышно по умолчанию.

**Рекомендация:** отдельная копия для вычитки, 720p и около 1–1,5 Мбит/с. Файл едет из
хранилища по сети на чужой машине, и 4K не даёт ничего: титры правят по звуку и по волне.

Команда — та же, что в репозитории программы,
`fs.manager.tauri/flows/SRT_EDIT_ON_SITE.md` §5. **Нормативна там**, здесь копия; расходиться
им нельзя, правите одну — правьте обе:

```bash
ffmpeg -i master.mov \
  -map 0:v:0 -map 0:a:0? \
  -c:v libx264 -profile:v high -pix_fmt yuv420p \
  -vf "scale='min(1280,iw)':-2" \
  -crf 27 -maxrate 1500k -bufsize 3000k -preset veryfast \
  -g 25 -keyint_min 25 -sc_threshold 0 \
  -c:a aac -b:a 128k -ac 2 \
  -movflags +faststart \
  source.mp4
```

Два параметра здесь не вкусовые, и раньше их в этой команде не было:

- **`-g` = частоте кадров, `-sc_threshold 0`** — ключевой кадр раз в секунду. Без них прыжок
  на реплику декодирует полминуты видео, а прыжки по репликам — это и есть основная работа в
  редакторе;
- **`-map 0:a:0?`** — звук обязателен: он ведёт часы превью, и из него же браузер считает
  общую волну. Немой прокси оставляет задачу без волны на линейке.

Частоту кадров прокси менять нельзя (`-r` в команде нет намеренно): сменили 25 → 30, и все
тайминги поехали относительно картинки.

`media.durationMs` и `media.fps` берутся из документа, а не из файла: инструмент не
разбирает контейнер.

## 2.4. `mix.peaks.json` — волна

Волна не считается в браузере: декодировать десятиминутный звук — это секунды фриза и сотни
мегабайт памяти, и результат не переживёт перезагрузку. Файл пиков — десятки килобайт и
рисуется мгновенно.

```jsonc
{
  "version": 1,
  "pps": 50,        // пар min/max в секунду
  "bits": 8,        // 8 или 16
  "dur": 718.4,     // длительность звука в секундах, дробная
  "data": "…"       // base64
}
```

**Раскладка `data`.** Распакованный base64 — плотный массив знаковых целых, попарно:
`min₀, max₀, min₁, max₁, …`. Одна пара описывает окно `1000 / pps` миллисекунд.

| `bits` | размер элемента | порядок байт | полная шкала | нормировка при чтении |
|---|---|---|---|---|
| `8` | 1 байт | — | ±127 | значение ÷ 128 |
| `16` | 2 байта | little-endian | ±32767 | значение ÷ 32768 |

Абсолютная величина не важна, важно соотношение: столбик рисуется размахом от `min` до
`max`, приведённым к высоте полосы.

**Пример.** Две секунды звука при `pps: 50` — это 100 пар, то есть 200 байт при `bits: 8`.
Пара `min = -64`, `max = 64` даёт при чтении `-0.5 … 0.5`, то есть столбик в половину высоты.

**Как это попадает на экран.** На каждый пиксель берутся все пары, попавшие в его диапазон
времени, и рисуется вертикальная линия от минимума до максимума. Когда пар на пиксель меньше
одной (сильный zoom-in), интерполяции нет — рисуются ступеньки: кривая, которой в данных нет,
выглядела бы точнее, чем есть.

**`pps` не меньше 50.** При 320 px/с и `pps = 50` на пиксель приходится примерно одна пара —
это предел, ниже которого волна становится ступенчатой на рабочем зуме.

Поле `dur` инструмент не использует для отрисовки — длину полотна задают `media.durationMs`
и реплики. Оно информационное.

## 2.5. `{no}/orig.srt` и `{no}/{lang}.srt` — сырьё титров

**Инструмент эти файлы не читает.** Их читает один раз нода обработки, когда собирает
`dialog.json`; дальше единственный источник правды — документ. В документе на них остаётся
только ссылка в `cues[].origin`:

```jsonc
"origin": { "kind": "auto", "file": "01/orig.srt", "index": 1 }
```

Зачем держать их в папке: по ним видно, что именно сказала автоматика до правок человека, и
повторный прогон может дописать новые реплики, не трогая старые.

Требования, если их собирает обработка: UTF-8 **без BOM**, обычный SRT — номер, строка
таймингов `hh:mm:ss,mmm --> hh:mm:ss,mmm`, текст, пустая строка. Имя языкового файла — код
языка (`es.srt`) либо суффикс имени, если нода настроена на `langFromName`.

Имя при этом не жёсткое: восстановление находит файл и по языку внутри имени
(`dialog_rus.srt`, `speaker_01_eng.srt`) — правила и их предел в §1.9. Требование к обработке
одно: **язык отдельным куском имени**, а оригинал — либо словом (`original`), либо своим
языком.

**Ни редактор, ни экспорт эти файлы не меняют.**

## 2.6. `{no}/audio.wav` и `{no}/audio.peaks.json` — стемы

Необязательны, и в обычной задаче их нет: дорожка в документе — это персонаж со своими
репликами, а звук нужен один, общий. Появились (кому-то понадобились для озвучки) — просто
заполняют `tracks[].audio` и `tracks[].peaks`, и редактор показывает свою волну дорожки и
даёт её слушать под `solo`.

Формат аудио: `wav` PCM 16 бит или `mp3`/`aac`, частота любая — играет браузер.

## 2.7. `exports/`

Производное. Обработка сюда **не пишет и отсюда не читает**: ни один экспортированный файл
не возвращается в документ. В текущей версии инструмент тоже сюда не пишет — экспорт уходит
файлом в браузер (§1.8, §5).

## 2.8. Минимальная рабочая задача

Один файл, и в нём обязательный минимум:

```json
{
  "format": "dialogDoc",
  "version": 1,
  "id": "dd_manual01",
  "revision": 0,
  "media": { "durationMs": 40000 },
  "languages": { "original": "en", "targets": [] },
  "tracks": [{ "id": "t01", "no": 1, "name": "Speaker" }],
  "cues": []
}
```

Инструмент откроется, покажет пустой список и даст завести реплики руками. Это не оговорка на
всякий случай, а рабочий режим: перевод вычитывают и без картинки.

Дальше по возрастанию удобства: `+ source.mp4` — появляется кадр и звук; `+ mix.peaks.json`
— появляется волна, а с ней видно, где реально началась речь.

## 2.9. Если раскладка другая

Раскладку `OUT` задаёт граф обработки, и она может быть любой. Инструмент не угадывает:

- **правило чтения `OUT`** настраивается у каждого проекта отдельно, в настройках
  инструмента: «папки первого уровня» (по умолчанию), «только `*.srt`», «всё содержимое».
  Так проект, где задача — не папка, всё равно виден в меню;
- **если `dialog.json` в папке нет**, задача не открывается. Сборка документа на месте по
  шаблону путей описана в плане (§8) и ещё не реализована.

## 2.10. Что должна и чего не должна делать обработка

### Порядок нод

Основной путь — распознавание с диаризацией:

1. **`transcribeVA`** в режиме `jsonfull` → `words.json`: слова с таймингами.
2. **Диаризация** → `diarization.json`: кто говорит и когда. Отдельная работа, описана в
   плане (§V.3).
3. **Экспорт видео для вычитки** → `source.mp4` по требованиям §2.3.
4. **`audioPeaks`** по общему звуку → `mix.peaks.json`; по стемам, если они есть, →
   `{no}/audio.peaks.json`.
5. **`dialogDocBuild`** — финализатор: создаёт папку задачи, раскладывает файлы, собирает
   `dialog.json`.

Простой путь, когда SRT уже готовы: шаги 1–2 не нужны, `dialogDocBuild` разбирает готовые
`orig.srt` и `{lang}.srt`.

Свойства `dialogDocBuild`, которые надо выставить осознанно:

| свойство | что задать |
|---|---|
| `taskPath` | `$localFolder/OUT/$clearName` — имя папки задачи видит человек |
| `speakerNames` | имена персонажей по порядку дорожек через запятую |
| `langFromName` | включить, если код языка закодирован в имени файла (`_es`, `.es`) |
| `origSuffix` | как узнать оригинальный SRT среди остальных |
| `rules` | `maxCps`, `minDurationMs`, `minGapMs` под конкретный материал |

### Повторный прогон: нода — первый автор, а не владелец

Прогон может случиться после того, как человек уже правил реплики. Поэтому при существующем
`dialog.json` нода:

- **дописывает** новые дорожки и новые реплики;
- **не трогает** существующие реплики, даже если распознавание изменилось;
- **не воскрешает** то, что перечислено в `removed`;
- **не трогает** `exports/`;
- **не сбрасывает** `revision` и не перезаписывает `updatedBy` человека своим значением.

Перезапись целиком уничтожила бы работу человека, а отказ дописывать оставил бы новые дорожки
невидимыми.

### Редактор тоже пишет в этот файл

Папка задачи — не только результат обработки, но и рабочий документ человека. Что делает
редактор при каждом сохранении, подробно в §1.7; для обработки важны три следствия:

1. **`revision` — рабочее поле, а не украшение.** По нему определяется, кто новее. Сброс в
   ноль или фиксированное значение выглядит для сайта как «версия старше нашей» и приведёт к
   слиянию там, где его не требовалось.
2. **Неизвестные поля не теряются.** Поле, которое обработка добавит под свою задачу,
   вернётся в файл после правок человека. Обратное тоже верно: нода обязана сохранять
   `voice`, `note`, `movedFrom` и всё, чего не знает.
3. **Файл пишется в каноническом виде** (§1.7). Если нода будет писать так же, `diff` между
   прогонами покажет смысловые изменения, а не переформатирование.

### Чего делать не должна

- писать в `exports/` — это производное;
- перезаписывать `dialog.json` целиком при дописывании;
- класть в `OUT` промежуточные файлы: они переживут задачу и запутают того, кто откроет
  папку через месяц;
- полагаться на имя персонажа в путях: имя меняется в редакторе, номер — нет;
- писать в документ абсолютные пути или пути с `..` — такой документ не откроется.

# Часть III. Полный пример папки

Задача: клип 40 секунд, два персонажа, оригинал английский, перевод испанский.

```
OUT/Notting_Hill/
  dialog.json          4 КБ
  source.mp4           6,1 МБ   H.264 720p + AAC, faststart
  mix.peaks.json       2,7 КБ   pps 50, bits 8, dur 40.0
  01/orig.srt          420 Б
  01/es.srt            460 Б
  02/orig.srt          380 Б
  02/es.srt            410 Б
```

`01/orig.srt`:

```
1
00:00:26,270 --> 00:00:29,190
So these guys just disappeared.

2
00:00:34,290 --> 00:00:36,000
You know it?
```

`dialog.json` — как в §2.2.1, с двумя дорожками и четырьмя репликами.

Проверить комплект целиком, не собирая обработку, можно готовым генератором:

```bash
node scripts/make-dialog-fixture.mjs ./dialog-fixture            # общий звук + титры
node scripts/make-dialog-fixture.mjs ./dialog-fixture --stems    # плюс аудио по персонажам
node scripts/make-dialog-fixture.mjs ./dialog-fixture --no-media # только документ и титры
```

Он собирает воспроизводимый комплект: те же тайминги, те же длительности, тот же документ.
Нужен `ffmpeg` в `PATH` (кроме `--no-media`).

**Из настоящего проекта Cast Analyzer Next** папка задачи собирается импортёром — прототипом
ноды `dialogDocBuild`:

```bash
node scripts/import-castanalyzer.mjs \
  --project ~/DUB/Movie_02 --video ~/Movie.mp4 \
  --out ~/OUT/Movie [--stems] [--proxy]
```

`--stems` дополнительно кладёт `*_guide` дорожек персонажей и их волны, `--proxy` делает копию
видео 720p для вычитки. Видео всегда перекладывается через `ffmpeg` с `+faststart`, даже без
`--proxy`: копирование как есть оставляет `moov` в конце файла, и браузер не начинает играть,
пока не скачает всё. Документ пишется в том же каноническом виде, в каком его пишет редактор,
поэтому первое автосохранение не переформатирует файл.

# Часть IV. Проверка и приёмка

```bash
# документ по контракту: ошибки, замечания, порядок реплик, побайтовая запись
node scripts/check-dialog-doc.mjs OUT/Notting_Hill/dialog.json

# можно сразу папкой или несколькими
node scripts/check-dialog-doc.mjs OUT
```

Скрипт различает **ошибки** (файл невалиден, открывать нельзя) и **замечания** (нарушены
правила материала — показать человеку, но не отказывать).

**Чек-лист приёмки задачи:**

- [ ] `dialog.json` в корне папки задачи и проходит `check-dialog-doc` без ошибок;
- [ ] имя папки задачи узнаваемо человеком;
- [ ] папки дорожек — номера с ведущим нулём, `tracks[].no` совпадает с именем папки;
- [ ] `tracks[].name` — имена персонажей, а не `Speaker 1`;
- [ ] `revision` не сброшен в ноль при дописывании;
- [ ] все пути в документе относительные, файлы по ним существуют;
- [ ] видео играется в браузере и собрано с `faststart`;
- [ ] `mix.peaks.json` на месте, `pps` не меньше 50;
- [ ] `languages.targets` перечисляет ровно те языки, переводы которых есть;
- [ ] `origin` заполнен у всех машинных реплик;
- [ ] `voice` у дорожек и реплик сохранён как есть;
- [ ] в `OUT` нет промежуточных файлов, `exports/` обработкой не тронута;
- [ ] повторный прогон на уже правленной задаче ничего не потерял.

# Часть V. Ограничения текущей версии

Список честный: это то, чего в инструменте нет, а не то, что «работает частично».

| чего нет | следствие |
|---|---|
| журнала операций и восстановления после падения | между правкой и записью есть окно порядка секунды; упавшая в этот момент вкладка его потеряет |
| записи в `exports/` | экспорт уходит файлом в браузер, а не в папку задачи |
| `media.mix` как источника звука и часов | нет видео — нет и звука, даже если файл микса есть; часы ведёт программный таймер |
| WebAudio для стемов | аудио дорожек играется через `<audio>` с поправкой по дрейфу. На двух-трёх дорожках этого достаточно, на десяти будет слышно |
| виртуализации списка реплик | на нескольких тысячах реплик список станет тяжёлым |
| объединения дорожек в интерфейсе | операция в модели есть, кнопки нет |
| сборки `dialog.json` на месте по шаблону | папка без документа просто не откроется |
| мобильной версии | ниже 1024 px показывается заглушка |
