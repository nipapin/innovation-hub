# Простая правка файлов в производстве

Человек открывает файл этапа (форма, рабочая папка), правит его простыми
действиями и сохраняет **поверх**: то же место, то же имя, тот же id файла.
Картинки и текст правятся прямо в браузере. Видео и звук — на машине, через
обычную очередь конвейера.

**Статусы:** ✅ работает · 🔧 частично · ⬜ не сделано

Связанные документы:

- [PRODUCTION_PLAN.md](./PRODUCTION_PLAN.md) — производство целиком.
- [COMPANY_PIPELINE_PLAN.md](./COMPANY_PIPELINE_PLAN.md) — свои машины компании и общие.
- [CONVERT_CONTROL_PLAN.md](./CONVERT_CONTROL_PLAN.md),
  [VIDEO_ADJUST_CONTROL_PLAN.md](./VIDEO_ADJUST_CONTROL_PLAN.md) — что машина уже
  умеет: конвертацию и кадрирование с фоном.

---

## 1. Общее для всех правок ✅

**Сохранение поверх.** Новые байты пишутся в тот же объект хранилища, что у файла
(как `overwrite` в `/api/storage/v1/presign`). Строка каталога, id и имя остаются,
журнал получает событие `put`, автором правки становится тот, кто сохранил.

- `POST /api/production/steps/{step}/files/{file}/replace`:
  - `{ stage: "presign", sizeBytes }` возвращает подпись на PUT в ключ файла;
  - `{ stage: "complete" }` записывает событие.
- Право: этап открыт, человек — исполнитель этапа или автор пайплайна. Файл должен
  лежать в рабочей папке этого этапа (`lib/production/uploads.ts`,
  `presignFileReplace` / `completeFileReplace`).

## 2. Картинки и текст — в браузере ✅

Окно просмотра файла этапа (`components/account/production/file-preview-dialog.tsx`),
кнопка «Редактировать».

- **Картинка** (jpg, png, webp — то, что браузер умеет и прочитать, и записать):
  обрезка рамкой, поворот на 90°, отражение, яркость, контраст, насыщенность,
  кисть, текст, отмена последней пометки. Всё считается на canvas
  (`components/account/production/image-editor.tsx`), сохраняется тем же форматом.
- **Текст** (`txt`, `srt`, `vtt`, `lrc`, `json`, `csv`, `tsv`, `md`): поле на весь
  файл, сохранение в UTF-8.
- Остальные форматы картинок (tiff, tga, psd, pdf) браузер записать не может —
  кнопки правки у них нет.

## 3. Видео и звук — на машине ⬜

Правка: подрезка, кадрирование, поворот и отражение, цвет, громкость,
нарастание и затухание звука, нормализация, формат.

### 3.1. Как это идёт

1. **Редактор на сайте** (позже) собирает правку одним JSON — §4. Сырой команды
   ffmpeg с сайта нет и не будет: машина не должна исполнять произвольную строку,
   пришедшую из браузера.
2. **Служебный проект.** Сайт копирует исходник в скрытый служебный проект:
   - у компании — проект служебного пользователя компании (`users.kind = 'company_wallet'`);
   - у личного аккаунта — служебный проект владельца.

   Пользователи этот проект не видят, в списках проектов его нет. Раскладка:
   `edits/{jobId}/IN/{имя исходника}`, результат — `edits/{jobId}/OUT/`.
3. **Задача** ставится в обычную очередь (`tasks`, `lib/pipeline/queue.ts`). Выбор
   машины работает сам:
   - у компании есть свои машины — задачу берут только они;
   - своих нет — берёт любая общая;
   - у компании включено «только свои машины» — задача ждёт свою машину.
4. **Ожидание.** Окно редактора опрашивает статус задачи. Результат пришёл, пока окно
   открыто, — показываем его с пометкой «обработано».
5. **Сохранить** кладёт результат на место исходника поверх (§1), имя то же.
   Окно закрыли раньше — результат ждёт в служебном проекте, сохранить можно потом.
   Несохранённые результаты удаляются через 7 дней.
6. **Оплата не берётся.** Задача помечается как бесплатная (`description.payBase = "none"`),
   списания по ней нет ни у кого.

### 3.2. Что сделать на сайте ⬜

- Служебный проект компании и владельца: заводится при первой правке, скрыт из
  списков и из поиска.
- Таблица задач правки: файл и этап, откуда начали, id задачи, статус, путь результата.
- Постановка задачи без скана папки: payload собирается сразу (§5), минуя `scan.ts`.
- Ожидание в окне редактора и «Сохранить поверх» (§1).
- Отключение оплаты для таких задач.
- Редактор видео и звука на сайте: таймлайн с подрезкой, рамка кадра, ползунки цвета
  и громкости, выбор формата.

## 4. Формат правки: `mediaEditSettings`, версия 1

Одна строка с JSON — по тем же правилам, что `convertSettings` и
`videoAdjustSettings`. Всё необязательно: поле не задано — этой правки нет.

```json
{
  "version": 1,
  "kind": "video",
  "trim":    { "start": 1.5, "end": 12.0 },
  "crop":    { "x": 0, "y": 140, "width": 1920, "height": 800 },
  "rotate":  90,
  "flipH":   false,
  "flipV":   false,
  "color":   { "brightness": 0.05, "contrast": 1.1, "saturation": 1.2, "gamma": 1.0 },
  "audio": {
    "mute":      false,
    "gainDb":    -3,
    "fadeIn":    0.5,
    "fadeOut":   1.0,
    "normalize": true
  },
  "output":  { "extension": "mp4", "quality": "normal" }
}
```

| Поле | Значение | Подсказка для ffmpeg |
| --- | --- | --- |
| `kind` | `"video"` или `"audio"` | `audio` — видеоразделы игнорируются |
| `trim.start`, `trim.end` | секунды от начала исходника, `end > start` | `-ss` / `-to` (точно, не по ключевым кадрам) |
| `crop` | пиксели **исходного** кадра, до поворота | `crop=w:h:x:y` |
| `rotate` | `0`, `90`, `180`, `270` по часовой | `transpose` |
| `flipH`, `flipV` | отражение после поворота | `hflip`, `vflip` |
| `color.brightness` | −1…1, 0 — без изменений | `eq=brightness` |
| `color.contrast` | 0…2, 1 — без изменений | `eq=contrast` |
| `color.saturation` | 0…3, 1 — без изменений | `eq=saturation` |
| `color.gamma` | 0.1…3, 1 — без изменений | `eq=gamma` |
| `audio.mute` | убрать звук | `-an` |
| `audio.gainDb` | −30…+20 дБ | `volume=XdB` |
| `audio.fadeIn`, `audio.fadeOut` | секунды | `afade=t=in` / `afade=t=out` (от конца подрезки) |
| `audio.normalize` | выровнять громкость | `loudnorm` |
| `output.extension` | расширение результата; по умолчанию как у исходника | контейнер |
| `output.quality` | `"high"`, `"normal"`, `"small"` | те же заготовки, что у Convert File (v2): crf, preset, битрейт |

Порядок применения: подрезка → кадрирование → поворот и отражение → цвет → звук →
кодирование. Если `output.extension` совпадает с исходником и правок кадра нет
(только подрезка или только звук), видео лучше не перекодировать (`-c:v copy`).

## 5. Что сделать в программе ⬜

Эта часть — для настольной программы (`fs.manager.tauri`).

### 5.1. Новый узел «Простая правка» (`mediaEdit`)

- Тип узла: `mediaEdit`. Одно свойство — `mediaEditSettings`: строка с JSON из §4.
- Вход: один файл (видео или звук) — `output` шага `mainSearch`, как у остальных узлов.
- Выход: **один** файл в папку результата задачи. Имя — как у исходника; расширение
  — из `output.extension`, если оно задано.
- Сборка команды ffmpeg — по таблице §4, на машине. Неизвестная `version` или
  неверное поле — шаг `error` с понятным текстом, без запуска ffmpeg.
- Прогресс: проценты по времени ffmpeg (`out_time` от длины после подрезки) — через
  обычный `reportTaskProgress`.

### 5.2. Как задача придёт

Обычная задача очереди (claim → progress → complete) с тем же `mch_`/`rc_`-токеном.
Payload собирает сайт:

```json
{
  "schemaVersion": 1,
  "processingQueue": ["mainSearch", "edit"],
  "description": {
    "dbItemId": "<id задачи>",
    "projectId": "<служебный проект>",
    "curItem": "<имя исходника>",
    "isFolder": false,
    "folderPath": "edits/<jobId>/IN",
    "payBase": "none",
    "purpose": "media-edit"
  },
  "mainSearch": { "output": [{ "fileId": "…", "s3Key": "…" }] },
  "edit": { "type": "mediaEdit", "mediaEditSettings": "{…json из §4…}" }
}
```

Результат машина пишет в `edits/<jobId>/OUT/` того же служебного проекта и
перечисляет его в `outFiles` при `completeTask` — так же, как сейчас.

### 5.3. Что важно

- Задача с `payBase: "none"` в статистике и оплате машины считаться не должна.
- Один исходник — одна задача: правка не ищет файлы по папке и не идёт дальше по графу.
- Окно редактора на сайте ждёт результат, поэтому эти задачи стоит брать раньше
  обычных, если машина умеет приоритеты. Не умеет — не страшно.

### 5.4. Как проверить

1. Видео 1080p, 30 с: подрезка 5–15 с, `crop` полосы сверху и снизу, `rotate: 90`,
   `gainDb: -6`. Результат: 10 с, кадр повёрнут и обрезан, звук тише.
2. Звук (`kind: "audio"`, wav): подрезка, `fadeIn` и `fadeOut`, `normalize`,
   `output.extension: "mp3"`. Результат — mp3 той же длины, что подрезка.
3. `{ "version": 2 }` — шаг `error` с текстом про версию, ffmpeg не запускался.
4. Только подрезка, тот же формат — видео не перекодировано, время обработки — секунды.
