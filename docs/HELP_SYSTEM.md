# Справка: база знаний по параметрам интерфейса

Объяснение «почему так, а не иначе» для каждого параметра сайта, доступное
прямо из того места, где параметр правят.

**Статусы:** ✅ работает · 🔧 частично · ⬜ не сделано

Состояние: 🔧 механизм работает, размечен раздел «Конвейер» — статья о разделе
и «Общие словари» с параметрами (8 статей). Остальное не написано.

---

## 1. Зачем

Настройки этого проекта почти всегда содержат неочевидное решение: порядок
записей в словаре значим, обход не берёт файл повторно, правка расходится на
весь парк машин. Эти «почему» написаны — но в `docs/` и в комментариях кода, то
есть там, где их не увидит ни оператор, ни клиент.

Подсказка в одну строку рядом с полем отвечает на вопрос «что это». Она не может
ответить на «почему так» — и не должна: строка на пять предложений в интерфейсе
не читается. Справка — это второй уровень, к которому подсказка ведёт.

## 2. Из чего состоит

| часть | где | что делает |
|---|---|---|
| реестр тем | `lib/help/topics.ts` | какие темы есть, кому видны, что с чем связано |
| статьи | `content/help/<lang>/<id>.md` | сами тексты |
| чтение | `lib/help/articles.ts` | файл → статья, фолбэк на русский |
| якорь у параметра | `components/help/help-dot.tsx` | знак «?» с поповером |
| якорь у страницы | `components/help/help-page-button.tsx` | иконка при названии раздела, плюс F1 |
| модалка | `components/help/help-modal.tsx` | статья поверх страницы, с переходами внутри |
| отдача статьи | `app/api/help/[id]/route.ts` | шапка, а с `?full=1` — тело; права проверяются здесь |
| страницы | `app/help/` | индекс с поиском и страница статьи |
| проверка | `scripts/help-check.mjs` | `npm run help:check` |

### Два уровня входа

Вопросы разные, поэтому и входа два:

| | знак «?» у параметра | иконка при названии раздела |
|---|---|---|
| отвечает на | почему эта настройка так устроена | что вообще делает раздел |
| что открывает | поповер с фразой + ссылка на статью | модалку со статьёй целиком |
| где стоит | вплотную к параметру или к его подсказке | сразу после заголовка, в той же строке |
| как подключается | `<HelpDot id="…" />` | проп `help` у `AdminPageHeader` / `AccountPageHeader` |

**Это единый стиль на все инструменты продукта, а не решение одной страницы**
([UI_GUIDE.md](./UI_GUIDE.md) §0, правило 13). Иконка спасательного круга и чип
`F1`, без подписи, сразу после названия — одинаково в админке и в кабинете.
Своей вёрстки входа быть не должно: оба заголовочных компонента уже принимают
`help`, и место кнопки задано в них.

Почему так, а не строкой под описанием (как было в первой версии): подпись
«Справка по разделу» читалась как ещё один абзац шапки и спорила с описанием за
внимание. Иконка при заголовке — привычная форма, а `F1` рядом объясняет себя
сам.

Модалка, а не переход на `/help/<id>`: на рабочей странице живое состояние —
слежение запущено, задачи раскрыты, идут тики опроса, — и уводить с неё ради
абзаца значит терять контекст. Ссылки внутри модалки меняют статью на месте;
для чтения подряд есть `/help` и ссылка «открыть целиком».

**Договорённость:** атрибут `help="…"` в разметке значит тему справки и ничего
другого. На этом стоит проверка якорей — чужой проп с тем же именем её сломает.

### Шапка статьи

```markdown
---
title: Типы файлов
summary: Одна фраза — её показывает поповер у знака «?».
updated: 2026-09-04
tags: конвейер, словари, расширения
---
```

Всё четыре поля обязательны. Формат шапки — плоские пары `ключ: значение`, без
вложенности и без YAML: разбор написан руками (`parseFrontmatter`), и всё, что
сложнее пары, он не поймёт.

`updated` ставится руками и означает «текст сверен с интерфейсом», а не «файл
тронут». Поэтому не `mtime`: правка опечатки не должна выглядеть как сверка.

`tags` — на языке статьи, поэтому и лежат в статье, а не в реестре: фильтр по
тегам работает внутри текущего языка.

## 3. Почему файлы, а не база

«Почему так, а не иначе» меняется ровно тогда, когда меняется код. В файле оно
видно в диффе рядом с правкой, из-за которой устарело; в базе — разъезжается
молча, и заметить это некому.

Цена решения: правка справки требует деплоя. Это осознанный размен. Если
понадобится править без деплоя, поверх файлов кладётся оверрайд из базы —
`loadArticle` остаётся единственной точкой чтения, ломать ничего не придётся.

## 4. Что проверяется автоматически

`npm run help:check`:

1. у каждой темы есть файл `content/help/ru/<id>.md`;
2. шапка полна и `updated` — дата;
3. нет файлов без темы в реестре;
4. каждая тема, кроме `standalone`, упомянута в коде интерфейса;
5. каждый якорь — `<HelpDot id="…">` и `help="…"` — ведёт на существующую тему;
6. `seeAlso` ссылается на существующие темы;
7. ссылки `/help/<id>` внутри статей ведут на существующие темы.

Отсутствие английского перевода — предупреждение, а не ошибка: статьи пишутся
по-русски, перевод догоняет.

Без этой проверки затея мертва через полгода. Справка гниёт тихо: параметр
переименовали, статью не тронули — и человек читает про настройку, которой уже
нет. Проверка переводит гниение из незаметного в ломающее сборку.

## 5. Права: не «спрятать абзац», а «другая статья»

`audience` темы — либо `"user"` (любой вошедший), либо тег права
(`lib/admin-capabilities.ts`). Видимость считается на сервере, до рендера:
спрятать ссылку мало, текст не должен попадать в бандл.

Ключевое решение: **одна настройка для пользователя и для админа — это две
статьи, а не одна с обрезкой.** Пользователю про типы файлов нужно «почему мой
файл не подхватился», админу — порядок доменов, ревизии и разъезд на парк машин.
Склейка даёт текст, плохой для обоих. Пара живёт двумя темами, связанными через
`seeAlso`:

```
pipeline.settings.file-type   audience: settings.write
pipeline.file-types           audience: user
```

Тема, до которой человеку не открыт интерфейс, отвечает **404, а не 403**: иначе
перебором id читается карта чужих разделов.

## 6. Как добавить статью

1. Запись в `HELP_TOPICS` (`lib/help/topics.ts`): `id`, `section`, `audience`.
2. Файл `content/help/ru/<id>.md` с шапкой.
3. Вход в статью — один из двух:
   - `<HelpDot id="<id>" />` рядом с параметром;
   - `help="<id>"` у `AdminPageHeader`, если статья про раздел целиком.

   Либо `standalone: true`, если входа пока нет и это осознанно.
4. `npm run help:check`.

Идентификатор — точечный путь от раздела к параметру
(`pipeline.settings.file-type`). Он же URL статьи и ключ якоря; переименование
рвёт внешние ссылки, поэтому имя выбирается один раз.

### Как отредактировать существующую

Отдельного редактора нет и не планируется — правка идёт файлом в репозитории
(почему так — §3). Порядок:

1. Найти файл: `content/help/ru/<id>.md`. Идентификатор виден в адресе статьи
   (`/help/pipeline.settings.sweep`) и в `HELP_TOPICS`.
2. Править как обычный markdown. Доступно всё, что умеет GFM: заголовки,
   списки, таблицы, код, цитаты. Ссылка на соседнюю статью — `/help/<id>`,
   такая ссылка внутри модалки меняет статью на месте, а не уводит со страницы.
3. Поднять `updated`, если правка смысловая. Опечатку править без этого:
   поле значит «текст сверен с интерфейсом», а не «файл тронут».
4. `npm run help:check`.
5. Обычный деплой — статья едет вместе с кодом.

Посмотреть до деплоя: `npm run dev`, открыть `/help/<id>`. Страницы динамические
и читают файл на каждый запрос, поэтому достаточно обновить вкладку — перезапуск
сервера не нужен.

Права на правку — те же, что на код: доступ к репозиторию. Отдельной роли
«редактор справки» в системе нет.

## 7. Как писать статью

Механизм из предыдущих разделов сам по себе ничего не объясняет. Правила ниже —
про текст.

### Статья отвечает на «почему», подсказка — на «что»

У большинства параметров уже есть подпись в одну строку (`*Hint` в словарях).
Если статья пересказывает её другими словами — статья не нужна: у темы должен
быть свой вопрос, на который в строку не ответить.

Практическая проверка: если из текста нельзя понять, **какое решение было
принято и от какой альтернативы отказались**, статья ещё не написана.

### Порядок изложения

1. **Что это** — одно-два предложения, без предыстории.
2. **Почему так, а не иначе** — решение, альтернатива, причина отказа.
3. **Чем это НЕ является** — если параметр путают с соседним. Часто самый
   ценный раздел: словарь расширений против `searchExts` в графе — ровно тот
   случай, где путаница стоит дороже всего.
4. **Практическое следствие** — что человеку делать. «Добавить расширение в
   словарь недостаточно, нужно пересохранить граф».
5. **Ссылки** на соседние темы и на пару для другой аудитории.

Не обязательно все пять — но порядок именно такой: человек пришёл за ответом,
а не за экскурсией.

### Регистр зависит от аудитории

| | `audience: "user"` | тег права |
|---|---|---|
| точка входа | симптом: «файл не пошёл в обработку» | механизм: «порядок доменов значим» |
| чего не должно быть | имён полей `options.json`, ревизий, тегов прав | пересказа пользовательской статьи |
| чем кончается | что сделать и куда написать, если не помогло | чем чревата правка и что она задевает |

### Тон

- Утверждения проверяемые. «Побеждает верхний» написано потому, что подбор
  возвращает первое совпадение, — если код изменится, статья станет ложью,
  поэтому такие места и стоят рядом с `updated`.
- Без «просто», «очевидно», «достаточно лишь». Если бы это было очевидно,
  статья не понадобилась бы.
- Без будущего времени и обещаний. Описываем то, что работает сегодня; то, чего
  нет, — в §8 этого документа, а не в статье.

### Картинки

Файл кладётся в `public/help/<id>/`, ссылка пишется от корня:

```markdown
![Закладки словарей](/help/pipeline.settings/tabs.png)
```

То есть у картинки тот же адрес, что у самой статьи, плюс имя файла: статья —
`/help/pipeline.settings`, её иллюстрация — `/help/pipeline.settings/tabs.png`.
Найти картинки статьи и понять, к чему они относятся, можно не открывая текст.

`npm run help:check` следит за обеими сторонами: ссылка без файла — ошибка,
файл, на который никто не ссылается, — предупреждение. Иначе картинки копятся
после переписанных статей, и через год никто не знает, какие ещё нужны.

Технически это разрешено флагом `ownContent` у `MarkdownView`: у своего текста
картинке позволен путь от корня сайта (`ownContentSanitizeSchema`), у описания
проекта — по-прежнему только `https://` и base64. Разница не в перестраховке:
описание приходит из программы и правится кем угодно, а статью пишем мы.

Размер и формат: обычный `png`/`webp`, ширина под колонку статьи (760 px в
модалке) — картинка масштабируется по месту, но грузится как есть, поэтому
класть исходник с камеры незачем.

### Длина

Одна статья — один вопрос. Если текст не помещается в экран-полтора, это две
статьи, связанные `seeAlso`. Дробление безболезненно: id — это и есть URL,
новые темы просто добавляются в реестр, а `help:check` укажет на ссылки,
оставшиеся на старый id.

### Откуда брать материал

Из `docs/` и из комментариев в коде: «почему» в этом проекте по большей части
уже написано, но написано для того, кто читает исходники. Работа автора статьи —
не сочинить объяснение, а перевести существующее в регистр читателя и убрать
то, что относится к реализации, а не к решению.

## 8. Что не сделано ⬜

- английские версии статей: сейчас EN-интерфейс показывает русский текст с
  пометкой;
- разметка якорями остального интерфейса — размечен только диалог словарей;
- полнотекстовый поиск по телу статей (сейчас — по заголовкам, описаниям и
  тегам; тем сотни, а не десятки тысяч, и `tsvector` пока дороже пользы);
- статьи о разделах написаны только для «Конвейера»: проп `help` есть у обоих
  заголовочных компонентов, но подключён пока на одной странице;
- ссылки из текстов ошибок и пустых состояний — самое ценное место для справки
  (человек уже упёрся), но пока не размечено ни одно;
- ссылка на справку из шелла кабинета и админки: индекс `/help` открывается
  только по прямому адресу.
